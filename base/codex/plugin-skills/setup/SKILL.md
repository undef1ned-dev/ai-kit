## Исполнение в Codex

Задачу и флаги бери из текущего сообщения пользователя. Прочитай `AGENTS.md`, `PRODUCT.md` и `.aikit/profiles.json`, если они относятся к задаче. Для команд профиля используй его `root` и переопределённые `commands`, а не команды, выбранные по названию стека. Пользовательские инструкции имеют приоритет над рекомендациями скилла.

Если шаг требует субагента, используй локальное имя из `.codex/agents/*.toml` без префикса плагина. Предпочитай загруженную именованную роль. Если инструмент не умеет выбирать роль, передай доступному субагенту её `developer_instructions` и нужный контекст; передавай настройки модели только когда это поддерживается схемой инструмента. Не утверждай, что модель из TOML применена, если выбранный способ запуска её не применяет. Если инструменты делегирования недоступны, останови цепочку с объяснением, а не выдавай работу основного потока за запуск агентов.

Независимых тестировщика и ревьюера запускай до ожидания любого из них, затем дождись обоих; исправления передавай уже запущенному агенту доступным инструментом продолжения, если он есть. Лимит параллельности соблюдай. Не создавай пользовательские чаты вместо субагентов. Ключи и параметры запуска инструментов бери из фактической схемы текущей сессии.

Вопросы пользователю задаёт основной поток, а не субагент. Неполный или прерванный результат агента не считай успехом. Модель сама по себе не заменяет запуск проверок: в итог включай реально выполненные команды и их результаты. Операции git выполняй по скиллам `git-branch` и `git-commit`, учитывая режим команды и прямые указания пользователя.

Подключи проект к плагинам AIKit для Codex или выполни проверку без записи.

Найди корень плагина, поднимаясь от этого SKILL.md до предка с scripts/plugin-init.py и base/codex. Не используй фиксированное число уровней. Проверь рабочий Python 3.11+; на Windows допустим py -3 или полный путь. Python 2 и заглушка Store не подходят.

## Проверка --check
Если передан --check, запусти только:
python3 "<корень>/scripts/codex-doctor.py" --workspace .
Для JSON добавь --json. Скрипт читает конфигурацию и историю, не запускает модель, MCP-серверы или команды профиля. Перескажи error/warning/unknown и действия из отчёта; не изменяй настройки. Наличие конфигурации и история запуска не подтверждают готовность активной сессии: одобрение проверяется в /hooks, загрузка агентов — новой сессией, соединение MCP — отдельной проверкой. Код 1 означает ошибку конфигурации. Заверши запрос проверки.

## Подключение
1. Возьми профили/паки/пресет из запроса. Иначе прочитай manifests, root_markers и presets, предложи подходящий набор. Для существующей установки покажи текущие значения .aikit/plugin-init.json. Не меняй выбранный набор без ответа.
2. Сохрани commit из .aikit/settings.json. Если его ещё нет, спроси вместе с выбором профилей: ask — предложить сообщения и ждать выбора; auto — коммитить по правилам команды без вопроса. Ответ пользователя уже задан — не спрашивай снова.
3. Запусти один из вариантов:
python3 "<корень>/scripts/plugin-init.py" --runtime codex --profiles <a+b> [--packs <pack>] --commit <ask|auto>
python3 "<корень>/scripts/plugin-init.py" --runtime codex --preset <имя> --commit <ask|auto>
4. Проверь codex plugin list --marketplace aikit --json. Недостающий выбранный профиль/пак установи через codex plugin add <имя>@aikit в рамках запрошенного подключения. Агенты записываются из нативных TOML в .codex/agents; навыки поступают из плагинов, не переводятся при подключении.
5. Запусти codex-doctor.py и отчитайся по фактическому результату. Не удаляй прежние установки автоматически: предупреждение скрипта передай пользователю.

Отчёт: выбранные профили/паки, режим коммитов, AGENTS.md и сохранённый внешний текст, записанные контракты/каталог/агенты/память/PRODUCT.md, Python/хуки/MCP и ограничения проверки. Предложи заполнить PRODUCT.md, сохранить настройки в git и открыть новую доверенную сессию. Изменённые хуки требуют одобрения в /hooks. Для MCP OAuth используй codex mcp login <сервер> только если это требуется выбранному серверу; наличие конфигурации не означает успешный вход.

Установка добавляет только отдельный шаблон .codex/aikit-permissions.example.toml из нативного settings.toml; в активный config.toml профиль не записывает. В отчёте отделяй наличие профиля от активной защиты чтения .env. Не меняй default_permissions, sandbox_mode, approval_policy или trust автоматически; legacy sandbox может перекрывать профиль. Для явного выбора сначала покажи действующую конфигурацию и ограничения пользователю.
