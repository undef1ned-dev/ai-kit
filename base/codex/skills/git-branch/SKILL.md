## Исполнение в Codex

Задачу и флаги бери из текущего сообщения пользователя. Прочитай `AGENTS.md`, `PRODUCT.md` и `.aikit/profiles.json`, если они относятся к задаче. Для команд профиля используй его `root` и переопределённые `commands`, а не команды, выбранные по названию стека. Пользовательские инструкции имеют приоритет над рекомендациями скилла.

Если шаг требует субагента, используй локальное имя из `.codex/agents/*.toml` без префикса плагина. Предпочитай загруженную именованную роль. Если инструмент не умеет выбирать роль, передай доступному субагенту её `developer_instructions` и нужный контекст; передавай настройки модели только когда это поддерживается схемой инструмента. Не утверждай, что модель из TOML применена, если выбранный способ запуска её не применяет. Если инструменты делегирования недоступны, останови цепочку с объяснением, а не выдавай работу основного потока за запуск агентов.

Независимых тестировщика и ревьюера запускай до ожидания любого из них, затем дождись обоих; исправления передавай уже запущенному агенту доступным инструментом продолжения, если он есть. Лимит параллельности соблюдай. Не создавай пользовательские чаты вместо субагентов. Ключи и параметры запуска инструментов бери из фактической схемы текущей сессии.

Вопросы пользователю задаёт основной поток, а не субагент. Неполный или прерванный результат агента не считай успехом. Модель сама по себе не заменяет запуск проверок: в итог включай реально выполненные команды и их результаты. Операции git выполняй по скиллам `git-branch` и `git-commit`, учитывая режим команды и прямые указания пользователя.

# Именование веток — Conventional Branch

Все ветки именуются по спецификации
[Conventional Branch 1.1.0](https://conventionalbranch.org/).
Применяй её **всегда и автоматически**, даже без явной просьбы пользователя.

## Формат

```
<type>/<description>
```

## Типы

| type       | Когда использовать                                   | Откуда ветвиться                   |
|------------|------------------------------------------------------|------------------------------------|
| `feat`     | Новая функциональность (полная форма — `feature`)    | `develop`, если есть, иначе `main` |
| `fix`      | Исправление бага (полная форма — `bugfix`)           | `develop`, если есть, иначе `main` |
| `hotfix`   | Срочное исправление в проде                          | `main` (потом влить и в `develop`) |
| `release`  | Подготовка релиза                                    | `develop`, если есть, иначе `main` |
| `chore`    | Служебное: зависимости, конфиги, прочее              | `develop`, если есть, иначе `main` |
| `docs`     | Только документация                                  | `develop`, если есть, иначе `main` |
| `refactor` | Изменение кода без изменения поведения               | `develop`, если есть, иначе `main` |
| `test`     | Только тесты                                         | `develop`, если есть, иначе `main` |
| `ci`       | Конфигурация CI/CD                                   | `develop`, если есть, иначе `main` |
| `build`    | Сборка, зависимости, пакетный менеджер               | `develop`, если есть, иначе `main` |
| `perf`     | Улучшение производительности                         | `develop`, если есть, иначе `main` |
| `style`    | Форматирование без изменения логики                  | `develop`, если есть, иначе `main` |

- Спецификация задаёт `feat`/`feature`, `fix`/`bugfix`, `hotfix`, `release`,
  `chore`. Остальные типы таблицы — расширение команды: они совпадают
  с типами коммитов (скилл `git-commit`), их тоже пропускает хук AIKit.
- В репозитории используем **короткие** `feat/` и `fix/` — они совпадают
  с типами коммитов.
- Ветки `main`, `master`, `develop` — trunk, префикса не имеют.
- Спецификация также описывает префиксы AI-агентов (`ai/`, `claude/`,
  `codex/`, `copilot/`, `cursor/`; хук пропускает и `opencode/`). Используй их, только если
  пользователь явно попросил; по умолчанию — тип по смыслу задачи.
  Для worktree применяй те же типы веток.

## Правила для description

1. Только строчная латиница `a-z`, цифры `0-9` и дефис `-` между словами.
   Заглавные буквы, `_`, пробелы и кириллица запрещены.
2. Точка допустима для номера версии: `release/v1.2.0`.
3. Дефис и точка не идут подряд и не стоят в начале или конце description.
4. Коротко, но понятно, о чём работа: 2–5 слов на английском.
5. Номер задачи, если он есть, включается в description:
   `feat/issue-42-oauth-login`, `fix/proj-123-email-validation`.

## Примеры

```
feat/oauth-login
feat/issue-42-csv-report-export
fix/empty-list-crash
fix/proj-123-email-validation
hotfix/memory-leak-on-requests
release/v2.0.0
chore/update-dependencies
chore/ci-test-pipeline
docs/install-guide
refactor/http-client
```

## Поведение агента

- Одна задача — одна ветка. Не коммить напрямую в `main` / `develop`.
- Если тип или description неочевидны из задачи — предложи 2–3 варианта
  имени и дождись выбора пользователя. Если очевидны — создавай ветку сразу
  и сообщи её имя.
