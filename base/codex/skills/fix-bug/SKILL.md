## Исполнение в Codex

Задачу и флаги бери из текущего сообщения пользователя. Прочитай `AGENTS.md`, `PRODUCT.md` и `.aikit/profiles.json`, если они относятся к задаче. Для команд профиля используй его `root` и переопределённые `commands`, а не команды, выбранные по названию стека. Пользовательские инструкции имеют приоритет над рекомендациями скилла.

Если шаг требует субагента, используй локальное имя из `.codex/agents/*.toml` без префикса плагина. Предпочитай загруженную именованную роль. Если инструмент не умеет выбирать роль, передай доступному субагенту её `developer_instructions` и нужный контекст; передавай настройки модели только когда это поддерживается схемой инструмента. Не утверждай, что модель из TOML применена, если выбранный способ запуска её не применяет. Если инструменты делегирования недоступны, останови цепочку с объяснением, а не выдавай работу основного потока за запуск агентов.

Независимых тестировщика и ревьюера запускай до ожидания любого из них, затем дождись обоих; исправления передавай уже запущенному агенту доступным инструментом продолжения, если он есть. Лимит параллельности соблюдай. Не создавай пользовательские чаты вместо субагентов. Ключи и параметры запуска инструментов бери из фактической схемы текущей сессии.

Вопросы пользователю задаёт основной поток, а не субагент. Неполный или прерванный результат агента не считай успехом. Модель сама по себе не заменяет запуск проверок: в итог включай реально выполненные команды и их результаты. Операции git выполняй по скиллам `git-branch` и `git-commit`, учитывая режим команды и прямые указания пользователя.

Исправь баг через агентов профиля. Сначала тест, который ловит баг, потом фикс — так баг не вернётся.

Баг: (задача из сообщения пользователя)

Флаги в начале описания:
- `--no-test` — без тестировщика: тест на баг не пишется (шаг 2 пропускается), команда `test` профиля всё равно запускается (шаг 4);
- `--no-review` — без ревьюера профиля.

`--no-test` и `--no-review` можно указать вместе — для быстрых правок с экономией токенов: остаются воспроизведение, кодер и команды `lint`, `format`, `test`. Отключённого агента не запускай ни на одном шаге, в том числе на кругах исправлений.

## Шаг 0 — Контракт профиля

Прочитай `.aikit/profiles.json`: агенты профиля по ролям (`agents`), папка профиля (`root`), команды (`commands`), пути профиля (`path_signals`). Если файла нет — скажи, что AIKit не установлен в проект, и остановись.

На Windows в PowerShell команда профиля с `npx` или `npm` может упасть из-за ExecutionPolicy (`npx.ps1`): вызови `npx.cmd`/`npm.cmd` или выполни в Git Bash, ExecutionPolicy не меняй.

Выбери профиль бага так же, как `$implement-feature`: по путям из описания, стектрейса или логов, а без них — по `role` и `stack`. Если неочевидно — спроси.

## Шаг 1 — Воспроизведение

Найди причину до того, как что-то менять:
- собери, что известно: шаги, ожидаемое и фактическое поведение, текст ошибки, стектрейс;
- найди код, через который проходит сценарий, и место, где поведение расходится с ожидаемым;
- если можно — воспроизведи: команда `test` профиля для связанных тестов, запрос к API, скрипт.

Если баг не воспроизводится или данных не хватает — спроси пользователя: шаги, данные, окружение. Не чини наугад.

Итог шага:

```
=== BUG_REPORT ===
Симптом: <что видит пользователь>
Причина: <файл:строка — что не так>
Воспроизведение: <команда или шаги>
Затронуто: <файлы и сценарии>
=== END BUG_REPORT ===
```

## Шаг 2 — Тест на баг (`agents.tester`, не с `--no-test`)

Запусти тестировщика профиля с BUG_REPORT:
- напиши минимальный тест, который повторяет сценарий бага и проверяет правильное поведение;
- код не исправляй;
- выведи TESTER_RESULT.

Выполни команду `test` профиля в папке `root`. Новый тест должен упасть, и именно из-за бага. Если проходит или падает по другой причине — верни тестировщику с выводом команды.

Если тест на этот баг написать нельзя (верстка, окружение, внешний сервис) — скажи, почему, и опиши ручную проверку вместо теста.

## Шаг 3 — Фикс (`agents.coder`)

Запусти кодера профиля с BUG_REPORT и TESTER_RESULT (с `--no-test` — только с BUG_REPORT):
- минимальное изменение, которое устраняет причину, а не симптом;
- без попутного рефакторинга;
- тест из шага 2 не меняй (если он был);
- выведи CODER_RESULT.

## Шаг 4 — Проверка

1. `lint` и `format` профиля на изменённых файлах (пути относительно `root` вместо `{files}`).
2. `test` профиля целиком: новый тест проходит, старые не сломались.
3. Ревьюер профиля (`agents.reviewer`, не с `--no-review`) проверяет CODER_RESULT: исправлена ли причина, нет ли того же бага в похожих местах, не сломано ли соседнее поведение.

Если команда упала или ревьюер нашёл CRITICAL — верни кодеру. Не больше двух кругов, потом покажи пользователю, что осталось.

```
### Ревью
<замечания, если есть; с --no-review — «ревью пропущено»>

<похожие места, ручная проверка, если тест невозможен или пропущен флагом --no-test>
```
