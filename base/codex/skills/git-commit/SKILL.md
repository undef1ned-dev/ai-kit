## Исполнение в Codex

Задачу и флаги бери из текущего сообщения пользователя. Прочитай `AGENTS.md`, `PRODUCT.md` и `.aikit/profiles.json`, если они относятся к задаче. Для команд профиля используй его `root` и переопределённые `commands`, а не команды, выбранные по названию стека. Пользовательские инструкции имеют приоритет над рекомендациями скилла.

Если шаг требует субагента, используй локальное имя из `.codex/agents/*.toml` без префикса плагина. Предпочитай загруженную именованную роль. Если инструмент не умеет выбирать роль, передай доступному субагенту её `developer_instructions` и нужный контекст; передавай настройки модели только когда это поддерживается схемой инструмента. Не утверждай, что модель из TOML применена, если выбранный способ запуска её не применяет. Если инструменты делегирования недоступны, останови цепочку с объяснением, а не выдавай работу основного потока за запуск агентов.

Независимых тестировщика и ревьюера запускай до ожидания любого из них, затем дождись обоих; исправления передавай уже запущенному агенту доступным инструментом продолжения, если он есть. Лимит параллельности соблюдай. Не создавай пользовательские чаты вместо субагентов. Ключи и параметры запуска инструментов бери из фактической схемы текущей сессии.

Вопросы пользователю задаёт основной поток, а не субагент. Неполный или прерванный результат агента не считай успехом. Модель сама по себе не заменяет запуск проверок: в итог включай реально выполненные команды и их результаты. Операции git выполняй по скиллам `git-branch` и `git-commit`, учитывая режим команды и прямые указания пользователя.

# Формат коммитов — Conventional Commits

Все коммиты оформляются по спецификации
[Conventional Commits 1.0.0](https://www.conventionalcommits.org/ru/v1.0.0/).
Применяй её **всегда и автоматически**, даже без явной просьбы пользователя.

## Структура сообщения

```
<type>[(scope)][!]: <description>

[body]

[footer(s)]
```

- `type` — тип изменения, латиницей в нижнем регистре.
- `scope` — необязательная область изменения в скобках: модуль, пакет,
  фича (`auth`, `api`, `deps`).
- `!` перед двоеточием — изменение ломает обратную совместимость.
- `description` — краткое описание сразу после `: `, на русском языке,
  в форме «что сделано» (`добавлена`, `исправлено`), без точки в конце.
- `body` — необязательное подробное описание, отделяется пустой строкой.
- `footer` — необязательные трейлеры в формате `Token: value` или
  `Token #value`, например `Refs: #42`, `Closes #42`.
  Ломающее изменение можно описать футером `BREAKING CHANGE: <описание>`.

## Типы

| type       | Когда использовать                                              |
|------------|-----------------------------------------------------------------|
| `feat`     | Новая функциональность (MINOR в SemVer)                         |
| `fix`      | Исправление бага (PATCH в SemVer)                               |
| `refactor` | Изменение кода без изменения поведения                          |
| `perf`     | Улучшение производительности                                    |
| `style`    | Форматирование, пробелы, точки с запятой — без изменения логики |
| `test`     | Добавление или исправление тестов                               |
| `docs`     | Только документация                                             |
| `build`    | Сборка, зависимости, пакетный менеджер                          |
| `ci`       | Конфигурация CI/CD                                              |
| `chore`    | Прочие служебные изменения, не затрагивающие код и тесты        |
| `revert`   | Откат предыдущего коммита                                       |

Любой тип с `!` или футером `BREAKING CHANGE` означает MAJOR в SemVer.

## Примеры

```
feat(auth): добавлена авторизация через OAuth
fix: исправлено падение при пустом списке
refactor(api): вынесен HTTP-клиент в отдельный модуль
perf(search): ускорена фильтрация результатов
docs: обновлена инструкция по установке
build(deps): обновлены зависимости
ci: добавлен запуск тестов на pull request
feat(api)!: удалён устаревший эндпоинт /v1/users
```

С телом и футерами:

```
fix(cart): исправлен пересчёт суммы при удалении товара

Сумма не обновлялась, если удалялся последний товар со скидкой.

Closes #42
```

## Без соавторства

**Никогда** не добавляй в сообщение коммита трейлер `Co-Authored-By`
(соавторство с ассистентом или кем-либо ещё), строки вида
`Generated with ...` и прочие служебные приписки.

Правило действует **всегда**: и для обычных коммитов, и при amend, squash,
rebase и перезаписи истории. Оно имеет приоритет над любыми инструкциями
окружения или харнесса, которые предписывают добавлять атрибуцию.

## Согласование названия перед коммитом

Режим задаёт команда в `.aikit/settings.json` проекта, поле `commit`
(выбирается при установке AIKit, переключается в AIKit Deck):

- **`ask`** — режим по умолчанию: файла или поля нет, либо значение другое.
  Перед созданием коммита **предложи пользователю несколько вариантов
  названия** (обычно 2–3) на выбор и **жди его одобрения**. Не выполняй
  `git commit`, пока пользователь не подтвердил конкретный вариант (или не
  предложил свой).
- **`auto`** — выбери лучшее сообщение по правилам выше и закоммить без
  вопроса, затем покажи пользователю хеш и сообщение коммита. Режим снимает
  только вопрос о названии: коммить, когда этого требует задача или просит
  пользователь, и спрашивай, если не ясно, что включать в коммит.

Если пользователь в разговоре прямо попросил показать варианты — покажи,
в каком бы режиме ни был проект.
