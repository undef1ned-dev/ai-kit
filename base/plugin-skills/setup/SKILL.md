Подключи текущий проект к AIKit. Плагины уже дают агентов, скиллы, хуки и MCP-серверы; этот скилл записывает то, что принадлежит проекту.

## 1. Найди корень плагина

- В Claude Code корень плагина `aikit` — `${CLAUDE_PLUGIN_ROOT}`.
- В Codex переменная не подставляется: корень — папка на три уровня выше этого `SKILL.md` (`<корень>/base/plugin-skills/setup/SKILL.md`).
- В Antigravity корень плагина `aikit` — папка `~/.gemini/config/plugins/aikit` (на два уровня выше установленного `skills/setup/SKILL.md`, или на три уровня выше при запуске из репозитория кита).

Проверь, что там есть `scripts/plugin-init.py`. Дальше этот путь — `<корень>`.

## Проверить готовность — --check

Если пользователь передал `--check`, не выполняй подключение или изменение настроек. В Codex запусти Python 3.11+:

```bash
python3 "<корень>/scripts/codex-doctor.py" --workspace .
```

Для машинного отчёта добавь `--json`. На Windows используй рабочий Python 3.11+, а не Python 2 или заглушку Store. Скрипт только читает конфигурацию и отметки, делает запросы списков плагинов и MCP через CLI; модель, серверы MCP и команды профиля не запускает. Содержимое секретов, аргументов MCP и сообщений ошибок хуков в отчёт не попадает.

Перескажи `error`, `warning` и `unknown` с предложенными действиями. `ok` для конфигурации или истории не означает готовность активной сессии: одобрение хуков требует проверки в `/hooks`, загрузка агентов — новой сессии, соединение MCP — отдельной проверки. Старые и чужие отметки не подтверждают работу Codex. Код выхода 1 означает найденную ошибку конфигурации; исправления автоматически не применяются.

В Claude Code сообщи, что автоматический режим `--check` пока предназначен для Codex; настройку не запускай. На этом запрос проверки завершён.

## 2. Выбери профили и паки

Если пользователь передал аргумент (`vue-nuxt`, несколько профилей через `+`, имя пресета или паки) — используй его.

Иначе определи стек по проекту и предложи выбор:
- профили — папки `<корень>/profiles/*`; признаки стека — `root_markers` в `profile.manifest.json` (`nuxt.config.ts` и т. п.);
- пресеты — `<корень>/presets/*.json` (готовые наборы профилей и паков);
- паки — `<корень>/packs/*`.

Если `.aikit/plugin-init.json` уже есть — покажи текущие профили и паки и спроси, что поменять.

## 2а. Спроси, как коммитить

Вместе с выбором профилей спроси, как ассистенту оформлять коммиты:
- **`ask`** (по умолчанию) — предлагать 2–3 сообщения по Conventional Commits и ждать выбора;
- **`auto`** — выбирать сообщение по тем же правилам и коммитить без вопроса.

Если `.aikit/settings.json` уже есть — покажи текущее значение `commit` и не меняй его без ответа. Настройка общая для команды; позже её можно переключить в AIKit Deck (`/deck`) или в самом файле.

## 2б. Проверь Python

На Python работают подключение проекта и хуки AIKit. Хуки вызывают `python3`, в Codex на Windows — `python`. Проверь команду, которую вызывают хуки этого runtime (в Codex на Windows замени `python3` на `python`):

```bash
python3 -c "import sys; print(sys.executable, sys.version_info >= (3, 9))"
```

Python исправен, если команда напечатала путь к интерпретатору и `True`. На Windows не годятся:
- путь внутри `WindowsApps` или пустой вывод — это заглушка Microsoft Store, а не Python;
- ошибка запуска (`py -3` падает, например, с `SRE module mismatch`) — сломанный или смешанный лаунчер.

Тогда попробуй `python` и `py -3` той же проверкой. Подошла другая команда — запусти ею скрипт подключения, а в отчёте предупреди, что хуки, вызывающие неисправную команду, работать не будут. Не подошла ни одна — остановись: попроси поставить Python 3.9+ (python.org или `winget`) и выключить заглушки `python.exe` и `python3.exe` в «Параметры → Приложения → Псевдонимы выполнения приложений».

## 3. Запусти подключение

Runtime — `claude` в Claude Code, `codex` в Codex, `antigravity` в Antigravity.

```bash
python3 "<корень>/scripts/plugin-init.py" --runtime <claude|codex|antigravity> --profiles <a+b> [--packs devops] --commit <ask|auto>
# или готовый набор
python3 "<корень>/scripts/plugin-init.py" --runtime <claude|codex|antigravity> --preset <имя> --commit <ask|auto>
```

`python3` — команда, которая прошла проверку в шаге 2б.

## 4. Проверь плагины профилей

Плагины профилей и паков должны быть установлены:
- Claude Code — `/plugin install <профиль>@aikit` для каждого профиля и пака. Скрипт уже включил их в `.claude/settings.json`: участники команды получат их после доверия папке проекта.
- Codex — `codex plugin add <профиль>@aikit`. Агенты Codex скрипт записал в `.codex/agents/`.
- Antigravity — `python3 "<корень>/scripts/install-antigravity-plugins.py" --workspace .` (устанавливает ядро `aikit`, выбранные профили и паки в `~/.gemini/config/plugins/`). Агенты проекта скрипт записал в `.agents/agents/`.

## 5. Отчёт

```
✅ AIKit подключён

Профили:  {список}
Паки:     {список или —}
Коммиты:  {спрашивать сообщение | автоматически по правилам}
Правила:  {CLAUDE.md | AGENTS.md} — блок AIKit, остальной текст файла не тронут
Записано: .aikit/profiles.json, .aikit/settings.json, .aikit/memory/, PRODUCT.md{, .claude/settings.json | , .codex/agents/}

Готовность:
  Python:  {✅ <команда> <версия> | ⚠ <что не так и как исправить>}
  Хуки:    {✅ запускались: <события>, Python <версия> | ⏳ ещё не запускались | ⚠ <причина и что сделать>}
  MCP:     {✅ входа не требуют | ⚠ нужен вход: <серверы> — <как войти>}

Дальше:
  1. Заполни PRODUCT.md — агенты читают его для контекста
  2. Закоммить изменения, чтобы команда получила те же настройки
  3. Перезапусти сессию, чтобы подхватились правила и агенты
```

Как заполнить «Готовность»:
- **Codex** — сначала выполни `scripts/codex-doctor.py` из корня плагина по команде раздела `--check` и используй его отчёт. Не считай неизвестное одобрение хуков или наличие MCP-конфигурации подтверждением работы. Дальнейшие пункты применяй с учётом этой границы проверки.
- **Python** — итог шага 2б для команды, которую вызывают хуки этого runtime.
- **Хуки** — «включены», «одобрены» и «выполняются» — три разных состояния: включённый и одобренный хук всё равно может падать при запуске, и тогда защита `.env` и проверки молча не работают. Узнай по отметкам, которые хуки оставляют при каждом запуске. Из корня проекта (скрипт подключения уже создал `.aikit/`) выполни `python3 "<корень>/base/hooks/aikit_hook.py" --status` — команда, которая прошла проверку в шаге 2б; она печатает JSON с полем `state`:
  - `ok` — хуки запускались (`events` — какие события, `python` — какой интерпретатор): `✅`.
  - `no-mark` — отметки нет, хуки в этом проекте ещё не запускались. Сразу после подключения это нормально: `SessionStart` сработает при следующем запуске сессии. Напиши `⏳` и попроси после перезапуска повторить `--status` или `/aikit:setup`. Если сессия уже перезапускалась, а отметки нет: в Codex хуки не одобрены (одобри хуки AIKit в `/hooks`, после обновления кита — снова) или не запускаются; в Claude Code проверь `/hooks`.
  - `internal-error` — хук запустился, но упал внутри (`last_error`: событие, время, текст): `⚠`, перескажи ошибку и предложи завести issue; действие при этом не блокируется.
  - `launcher-error` — хук не смог стартовать: `python` в PATH старый или заглушка, а `py -3` и `python3` не подошли (`details`): `⚠`, предложи шаг 2б — поставить Python 3.9+ и выключить заглушки.
  Проба в этой сессии не заменяет отметку: твой shell — не окружение хука. В Codex на Windows отметка — единственное доказательство, что хуки выполняются; правила из `AGENTS.md` действуют и без них.
- **MCP** — серверы из `mcp.json` ядра и выбранных профилей и паков (`<корень>/base/mcp.json`, `<корень>/profiles/<профиль>/mcp.json`, `<корень>/packs/<пак>/mcp.json`). Сервер с полем `url` — удалённый, ему нужен вход через OAuth (например, `figma`): в Claude Code — `/mcp` → сервер → Authenticate, в Codex — `codex mcp login <сервер>`. Без входа такой сервер пишет ошибку авторизации в каждой сессии и каждому агенту, а остальная работа идёт. Серверы с `command` (`npx …`) входа не требуют.

Если скрипт напечатал предупреждение про `attach.sh` — перескажи его пользователю: копии агентов и скиллов в `.claude/` нужно удалить, иначе они дублируют плагины.
