Реализуй фичу через цепочку агентов профиля.

Фича: $ARGUMENTS

## Шаг 0 — Контракт профиля

Прочитай `.aikit/profiles.json`. Для каждого профиля в `profiles` там есть:
- `role` и `stack` — за какую часть системы отвечает профиль;
- `agents` — агенты по ролям `architect`, `coder`, `tester`, `reviewer`;
- `specialists` — дополнительные агенты и условие `when`, при котором их звать;
- `commands` — команды проекта `lint`, `format`, `test`, `build`, `run` (`{files}` — изменённые файлы);
- `path_signals` — пути, по которым задача относится к профилю.

Если файла нет — скажи, что AIKit не установлен в проект (`attach.sh` или установщик адаптера), и остановись.

Выбери профиль задачи:
- явные пути в задаче сравни с `path_signals`;
- без путей — сопоставь задачу с `role` и `stack`;
- профиль один — бери его.

Если задача затрагивает несколько профилей (например, новый эндпоинт и страница, которая его использует), пройди цепочку по каждому: сначала профиль с `role: backend` — он фиксирует API-контракт, затем остальные. ARCHITECT_PLAN backend-профиля передай архитектору следующего профиля.

Если профиль неочевиден — спроси пользователя, не угадывай.

## Шаг 1 — Архитектура (`agents.architect`)

Запусти архитектора профиля:
- прочитай PRODUCT.md, CLAUDE.md и похожий код проекта;
- спроектируй минимальный набор изменений;
- выведи ARCHITECT_PLAN.

Дождись результата.

## Шаг 2 — Специалист (если нужен)

Если задача или ARCHITECT_PLAN подходит под условие `when` одного из `specialists`:
- запусти агента специалиста с ARCHITECT_PLAN;
- его вывод передай кодеру, затем тестировщику и ревьюеру.

Специалист дополняет цепочку, а не заменяет её.

## Шаг 3 — Реализация (`agents.coder`)

Запусти кодера профиля с ARCHITECT_PLAN:
- реализуй все файлы по плану;
- выведи CODER_RESULT.

Дождись результата.

## Шаг 4 — Тесты и ревью (`agents.tester`, `agents.reviewer`)

Запусти одновременно:
- тестировщика профиля — тесты по CODER_RESULT;
- ревьюера профиля — проверка CODER_RESULT на соответствие стандартам профиля.

## Шаг 5 — Проверка командами профиля

Выполни команды из `commands` профиля, которые есть в контракте:
- `lint` и `format` — на изменённых файлах (подставь их вместо `{files}`);
- `test`.

Команды проекта могут отличаться от дефолтов кита — используй именно те, что в `.aikit/profiles.json`. Если команда упала — покажи вывод и верни задачу кодеру или тестировщику.

## Итог

```
## Фича реализована: <название>

### Профили и агенты
<профиль: architect → coder → tester + reviewer, специалисты если были>

### Созданные файлы
<список>

### Тесты
<список; результат команды test>

### Замечания ревью
<если есть — что нужно исправить>

### Следующие шаги
<миграции, ручные проверки; команда run профиля, если нужен запуск>
```

Если на любом шаге агент вернул вопросы или неоднозначности — остановись и уточни у пользователя перед продолжением.
