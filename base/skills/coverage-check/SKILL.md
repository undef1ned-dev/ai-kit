Проверь покрытие тестами силами quality-специалиста профиля.

$ARGUMENTS

## Шаг 0 — Профиль

Прочитай `.aikit/profiles.json`. Если файла нет — проект не подключён к AIKit: предложи `/aikit:setup` и остановись.

Выбери профили для проверки: если в аргументах есть путь — профиль, в чей `root` он попадает; иначе все профили проекта, по очереди.

## Шаг 1 — Анализ

Для каждого выбранного профиля возьми агента из `specialists.quality.agent` и запусти его с задачей:
1. Запустить тесты с coverage (команда `test` профиля с флагом покрытия)
2. Найти модули с критически низким покрытием (меньше 50%)
3. Для каждого такого модуля предложить конкретные тест-кейсы
4. Приоритизировать по бизнес-критичности: сервисы и состояние → API → UI → утилиты

Передай агенту путь из аргументов, если он есть.

Если у профиля нет `specialists.quality` — сделай анализ сам: команда `test` из `commands` с флагом покрытия стека, правила тестов из `CLAUDE.md`.

## Шаг 2 — Итог

Покажи QUALITY_REPORT каждого профиля и общий список «что покрыть первым». Тесты не пиши без согласия пользователя — предложи `/implement-feature` или тестировщика профиля.
