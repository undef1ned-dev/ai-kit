Создай новый скилл. Интервью ведёшь ты сам, в этом диалоге: агент `skill-builder` работает отдельно и спросить пользователя не может, поэтому он получает уже готовые ответы.

Назначение скилла: $ARGUMENTS

## Шаг 0 — Где запущено

Определи режим по корню рабочей папки:

- **кит** — есть `base/agents/`, `profiles/` и `scripts/build-plugins.py`. Создаём скилл кита. Для сложных правок кита основной путь — `/improve-aikit` (агент `aikit-maintainer`).
- **проект** — этих признаков нет. Создаём локальный скилл только для этого проекта, в кит он не попадает.

В режиме проекта ещё:
- **runtime** — по папкам в корне: `.claude/` → Claude Code, `.codex/` → Codex, `.opencode/` → OpenCode (`.agents/` сам по себе runtime не определяет). Найдено несколько или ни одной — спроси, для каких runtime создать скилл;
- **профиль** — из `.aikit/profiles.json`, если файл есть.

## Шаг 1 — Интервью

Задавай вопросы фазами, по одной фазе за сообщение, и жди ответов. Неполный ответ — уточни перед следующей фазой. Что уже есть в назначении скилла — не переспрашивай, а подтверди.

**Фаза 1 — Основы**
1. Имя — папка и вызов (`/name` в Claude Code, `$name` в Codex), kebab-case, глагол или действие: `setup-db`, `run-audit`.
2. Что делает, по схеме «запускает [что], чтобы [результат]».
3. Размещение:
   - кит — `base` (во всех проектах), профиль или пак: перечисли папки `profiles/*/` и `packs/*/`, которые есть в ките;
   - проект — только подтверди runtime из шага 0.
4. Аргументы — что пользователь передаёт после имени, или «без аргументов».

**Фаза 2 — Оркестрация агентов**
5. Какие агенты вызывает скилл. Список собери сам, не по памяти, и покажи пользователю:
   - кит — Glob `base/agents/*.md`, `profiles/*/agents/*.md`, `packs/*/agents/*.md`; скилл `base` берёт агентов профилей по ролям из `.aikit/profiles.json` (`agents`, `specialists`), а не по имени;
   - проект — Glob `agents/*.md` в `.claude/`, `.codex/agents/*.toml`, `.opencode/agents/*.md` и роли из `.aikit/profiles.json`;
   - или новый агент — создадим через `/create-agent`.
6. Порядок: последовательно, параллельно или смешанно — опиши схему.
7. Что передаётся между агентами (например, `ARCHITECT_PLAN` от архитектора кодеру), или «агенты независимы».

**Фаза 3 — Контекст и точки остановки**
8. Предусловия: что должно быть готово до запуска.
9. Когда скилл останавливается и спрашивает пользователя: агент вернул вопросы, файл уже существует, тесты упали.
10. Что скилл читает сам до запуска агентов — обычно это делают агенты.
11. Побочные эффекты (коммит, PR, запись в память, внешний сервис) — тогда скилл только по явному вызову.

**Фаза 4 — Результат**
12. Артефакты: файлы, отчёт, команды.
13. Финальный отчёт — структура.
14. Следующие шаги, которые скилл рекомендует.

## Шаг 2 — Файл скилла

Запусти агент `skill-builder` и передай ему режим, runtime (в проекте), профиль из `.aikit/profiles.json` и все ответы интервью. Он сверит имя с существующими скиллами, изучит конвенции и вернёт блок `SKILL_FILE`, ничего не записывая.

Если в `SKILL_FILE` есть `QUESTIONS` или `CONFLICTS` — покажи их пользователю, получи ответ и запусти `skill-builder` снова с уточнёнными ответами.

## Шаг 3 — Превью и запись

Покажи пользователю путь и полное содержимое каждого файла из `SKILL_FILE` и спроси: записать или что-то изменить? Правки — снова через `skill-builder`.

После подтверждения запиши файлы по путям из блока. Существующий файл не перезаписывай без отдельного подтверждения.
