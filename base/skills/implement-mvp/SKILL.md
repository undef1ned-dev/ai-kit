Составь технический план по MVP-документу. Вопросы пользователю задаёшь ты сам, в этом диалоге: агент `tech-planner` работает отдельно и спросить пользователя не может — он возвращает вопросы блоком `QUESTIONS`.

MVP или путь к документу: $ARGUMENTS

Если аргумент не передан — найди последний документ в `docs/mvp/` и уточни у разработчика, с каким работаем.

## Шаг 1 — План

Запусти агент `tech-planner` и передай ему путь к документу (или описание идеи). Агент должен:
1. Прочитать MVP-документ из `docs/mvp/`
2. Прочитать `PRODUCT.md` и `CLAUDE.md` для контекста стека
3. Определить какие профили проекта задействованы (`.aikit/profiles.json`: `role` — `backend`, `web`, …)
4. Спроектировать API-контракт если задействован Backend
5. Описать технический scope для каждой платформы
6. Определить порядок реализации и зависимости
7. Вывести блок `TECH_PLAN`

Если агент вернул `QUESTIONS` — задай их пользователю одним сообщением (каждый вопрос с пояснением и примерами ответов, как их дал агент), дождись ответов и запусти `tech-planner` снова: тот же документ плюс ответы. Повторных вопросов обычно нет; если они пришли снова — ещё один круг, не больше.

## Шаг 2 — Передача архитекторам

Покажи TECH_PLAN и спроси по задействованным профилям, например для backend + web:

> **TECH_PLAN готов. Передать в команду разработки?**
>
> По плану задействованы два профиля:
> — **<backend-профиль>** → архитектор `<agents.architect>`
> — **<web-профиль>** → архитектор `<agents.architect>`
>
> 💡 Рекомендуемый порядок: сначала backend — он зафиксирует API-контракт, затем web.
>
> Что запускать?
> - **"backend"** / **"web"** — по одному профилю
> - **"оба"** — оба последовательно (сначала backend)
> - **"нет"** — остановиться, TECH_PLAN сохранён в истории

Выбранные профили — запускай их архитекторов (`agents.architect` из `.aikit/profiles.json`) по очереди и передавай каждому TECH_PLAN:
- архитектор профиля с `role: backend` читает BACKEND SCOPE и API CONTRACT;
- архитектор профиля с `role: web` читает WEB SCOPE и API CONTRACT;
- ARCHITECT_PLAN backend-профиля передай архитектору следующего профиля.

Реализацию по каждому плану ведёт `/implement-feature`.
