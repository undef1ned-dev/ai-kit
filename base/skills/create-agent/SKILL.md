Создай нового агента. Интервью ведёшь ты сам, в этом диалоге: агент `agent-builder` работает отдельно и спросить пользователя не может, поэтому он получает уже готовые ответы.

Назначение агента: $ARGUMENTS

## Шаг 0 — Где запущено

Определи режим по корню рабочей папки:

- **кит** — есть `base/agents/`, `profiles/` и `scripts/build-plugins.py`. Создаём агента кита. Для сложных правок кита основной путь — `/improve-aikit` (агент `aikit-maintainer`).
- **проект** — этих признаков нет. Создаём локального агента только для этого проекта, в кит он не попадает.

В режиме проекта ещё:
- **runtime** — по папкам в корне: `.claude/` → Claude Code, `.codex/` → Codex, `.opencode/` → OpenCode (`.agents/` сам по себе runtime не определяет). Найдено несколько или ни одной — спроси, для каких runtime создать агента;
- **профиль** — из `.aikit/profiles.json`, если файл есть: стек и стиль подскажут примеры и правила.

## Шаг 1 — Интервью

Задавай вопросы фазами, по одной фазе за сообщение, и жди ответов. Расплывчатый ответ — уточни, не двигайся дальше. Что уже есть в назначении агента — не переспрашивай, а подтверди.

**Фаза 1 — Идентичность**
1. Имя в kebab-case: `docs-writer`, `db-migrator`, `api-designer`.
2. Роль одним предложением: что агент делает и чего НЕ делает. Пример: «Пишет тесты для сервисного слоя. Не меняет бизнес-логику».
3. Размещение:
   - кит — `base` (нужен во всех проектах), профиль или пак: перечисли папки `profiles/*/` и `packs/*/`, которые есть в ките, или новый профиль (`python3 scripts/new-profile.py`);
   - проект — только подтверди runtime из шага 0.
4. Модель — уровень:
   - `haiku` — простые частые задачи: поиск, форматирование, короткие проверки;
   - `sonnet` — большинство задач: код, анализ, генерация файлов;
   - `opus` — решения, где ошибка дороже всего: архитектура, ревью, безопасность.

**Фаза 2 — Инструменты и контекст**
5. Инструменты: `Read`, `Write`, `Edit`, `Bash`, `Grep`, `Glob`, `WebSearch`, `WebFetch` — только нужные.
6. Что агент читает перед работой: `PRODUCT.md`, правила проекта (`CLAUDE.md` / `AGENTS.md`), `.aikit/profiles.json`, похожий код проекта, выходной блок другого агента (например `ARCHITECT_PLAN`).
7. MCP-серверы: перечисли те, что уже подключены — в ките `mcp.json` слоя, в проекте `.mcp.json`, `[mcp_servers.*]` в `.codex/config.toml` или `mcp` в `opencode.json`, — или «не нужны».

**Фаза 3 — Алгоритм**
8. Шаги работы по порядку, минимум три.
9. Задаёт ли агент вопросы перед работой? Помни: запущенный как сабагент, он спросить не может — только вернуть вопросы вызвавшему.
10. Шаблоны кода или документов, которые агент обязан использовать, — пример или набросок.

**Фаза 4 — Правила качества**
11. Что обязательно в результате. Пример: «тест-файл рядом с реализацией».
12. Что запрещено. Пример: «не трогать существующие миграции».
13. Самопроверка перед завершением. Пример: «прогоняет линтер».

**Фаза 5 — Формат вывода**
14. Что создаёт агент: файлы (какие и куда), текст для следующего агента, отчёт.
15. Именованный выходной блок для цепочки (`ARCHITECT_PLAN`, `REVIEW_RESULT`) и его поля — или «не нужен».
16. Что агент выводит пользователю в конце.

**Фаза 6 — Интеграция**
17. Кто вызывает: пользователь, скилл, другой агент.
18. Кто работает до и после него, что передаётся.
19. Нужен ли скилл-обёртка — создадим отдельно через `/create-skill`.
20. Только в проекте: должен ли `/implement-feature` звать агента как специалиста профиля.

## Шаг 2 — Файл агента

Запусти агент `agent-builder` и передай ему режим, runtime (в проекте), профиль из `.aikit/profiles.json` и все ответы интервью. Он сверит имя с существующими агентами, изучит конвенции и вернёт блок `AGENT_FILE`, ничего не записывая.

Если в `AGENT_FILE` есть `QUESTIONS` или `CONFLICTS` — покажи их пользователю, получи ответ и запусти `agent-builder` снова с уточнёнными ответами.

## Шаг 3 — Превью и запись

Покажи пользователю путь и полное содержимое каждого файла из `AGENT_FILE` и спроси: записать или что-то изменить? Правки — снова через `agent-builder`.

После подтверждения запиши файлы по путям из блока. Существующий файл не перезаписывай без отдельного подтверждения.
