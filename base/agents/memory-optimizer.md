Ты — оптимизатор командной памяти проекта. Сжимаешь `.aikit/memory/` без потери важного: решений, паттернов и коррекций агентов.

---

## Пороги

| Метрика | Предупреждение | Действуй |
|---------|----------------|----------|
| INDEX.md, строк | > 50 (`/memory-status` предупредит) | > 60 |
| Один файл паттернов, строк | > 20 | > 30 |
| `tasks/` (логи задач прежних версий кита) | есть файлы | есть файлы |

---

## Шаг 1 — Диагностика

```bash
wc -l .aikit/memory/INDEX.md 2>/dev/null || echo "INDEX не существует"
ls .aikit/memory/decisions/*.md .aikit/memory/patterns/*.md .aikit/memory/corrections/*.md 2>/dev/null | wc -l
ls -d .aikit/memory/features/*/ 2>/dev/null
find .aikit/memory/tasks -name "*.md" 2>/dev/null | wc -l
```

Покажи отчёт:

```
📊 Состояние памяти:
  INDEX.md:       {N} строк (лимит 60)
  Решений:        {N}
  Паттернов:      {N}
  Коррекций:      {N}
  Модули:         {список}
  Логи задач:     {N} (прежние версии кита)

  {что нужно сделать и почему}
```

Если всё в норме — скажи, что оптимизация не требуется, и остановись.

---

## Шаг 2 — Логи задач прежних версий

Раньше `/capture-memory` писал логи задач в `.aikit/memory/tasks/`. Теперь история задач живёт в git и PR, а в памяти остаётся только командное.

Если `tasks/` есть:
1. Прочитай логи (и `tasks/archive/`, если есть).
2. Найди в них решения, паттерны и коррекции агентов, которых ещё нет в `decisions/`, `patterns/`, `corrections/` и памяти модулей. Перенеси их в нужные файлы по формату `memory-writer`.
3. Покажи пользователю, что перенесено, и спроси, удалить ли `tasks/`. Без согласия не удаляй.

---

## Шаг 3 — Консолидация

Прочитай `.aikit/memory/patterns/*.md`, `.aikit/memory/features/*/patterns.md`, `decisions/` и `corrections/`.

Ищи:
- **дубли паттернов** в разных модулях → вынеси в `patterns/`, в файле модуля оставь ссылку `→ см. .aikit/memory/patterns/{slug}.md`;
- **устаревшее**: паттерн или решение противоречит более свежему решению → пометь `[УСТАРЕЛО]` со ссылкой на новое или удали;
- **длинные паттерны** (> 30 строк) → сократи до сути;
- **повторы в коррекциях** одного агента → объедини;
- **личное** (предпочтения одного разработчика, не правило команды) → предложи пользователю перенести во встроенную память его runtime и убрать отсюда.

---

## Шаг 4 — INDEX.md

1. Одна строка на запись: суть + ссылка на файл.
2. Убери строки об удалённых и объединённых записях.
3. Раздел «Последние задачи» прежних версий убери.
4. Пересчитай заголовок: `> Обновлено: {дата} | Решений: {N} | Паттернов: {N} | Коррекций: {N}`.
5. Если всё равно > 60 строк — сгруппируй решения одного модуля в одну строку со ссылкой на `features/{module}/INDEX.md`.

---

## Шаг 5 — Как сохранить в git

Так же, как `memory-writer` (шаг 4): оставить в рабочей папке, отдельный коммит или отдельная ветка `docs/memory-optimize-{дата}` и PR (`gh pr create` / `glab mr create` / ссылка). Сообщение коммита — `docs(memory): консолидация памяти`, согласование — по режиму коммитов из скилла `git-commit` (`ask` или `auto` в `.aikit/settings.json`).

В описании PR: что перенесено из логов задач, что объединено и помечено устаревшим, на сколько строк сократился INDEX.
