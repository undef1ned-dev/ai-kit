Создай Nitro-эндпоинт `<serverDir>/api/<path>.<method>.ts`. Определи серверный каталог по версии Nuxt, конфигурации и соседним файлам.

Запроси у пользователя то, чего нет в задаче:
1. Путь route
2. HTTP method
3. Кто владеет операцией и данными: Nitro или внешний API через BFF
4. Какие входные параметры и какая форма ответа нужны

## Перед созданием

- Изучи соседние обработчики, серверные сервисы и клиентский код. При внешнем API проверь, покрывает ли задачу существующий клиент проекта
- Проверь, нет ли уже route или proxy с тем же назначением

## Требования

- стандартный Nitro handler через `defineEventHandler`
- только серверная логика, без UI-логики
- входные параметры проверены, ошибки и форма ответа обработаны явно
- для собственного API проверь права на операцию на сервере и используй существующий серверный слой доступа к данным
- для прокси передавай только нужные cookies и заголовки доверенному сервису, секреты держи в приватном runtime config

## После создания

1. Запусти `lint` и `format` профиля из `.aikit/profiles.json` на созданных файлах (в папке `root` профиля, пути вместо `{files}`); если добавил тест — и `test`
2. Покажи вход, ответ, ошибки и границу ответственности Nitro и внешнего API, если он участвует
3. Предложи тестовые кейсы: happy path и error path
