## Исполнение в Codex

Задачу и флаги бери из текущего сообщения пользователя. Прочитай `AGENTS.md`, `PRODUCT.md` и `.aikit/profiles.json`, если они относятся к задаче. Для команд профиля используй его `root` и переопределённые `commands`, а не команды, выбранные по названию стека. Пользовательские инструкции имеют приоритет над рекомендациями скилла.

Если шаг требует субагента, используй локальное имя из `.codex/agents/*.toml` без префикса плагина. Предпочитай загруженную именованную роль. Если инструмент не умеет выбирать роль, передай доступному субагенту её `developer_instructions` и нужный контекст; передавай настройки модели только когда это поддерживается схемой инструмента. Не утверждай, что модель из TOML применена, если выбранный способ запуска её не применяет. Если инструменты делегирования недоступны, останови цепочку с объяснением, а не выдавай работу основного потока за запуск агентов.

Независимых тестировщика и ревьюера запускай до ожидания любого из них, затем дождись обоих; исправления передавай уже запущенному агенту доступным инструментом продолжения, если он есть. Лимит параллельности соблюдай. Не создавай пользовательские чаты вместо субагентов. Ключи и параметры запуска инструментов бери из фактической схемы текущей сессии.

Вопросы пользователю задаёт основной поток, а не субагент. Неполный или прерванный результат агента не считай успехом. Модель сама по себе не заменяет запуск проверок: в итог включай реально выполненные команды и их результаты. Операции git выполняй по скиллам `git-branch` и `git-commit`, учитывая режим команды и прямые указания пользователя.

Создай TileEntity по правилам проекта (`AGENTS.md`, профиль `forge-1-12-java`).

## Перед созданием

- Папка мода — `root` профиля `forge-1-12-java` в `.aikit/profiles.json`
- Найди класс блока и существующие TileEntity проекта — следуй их стилю
- Если блока ещё нет — сначала скилл `forge-1-12-new-block`

## Что создать

1. `tileentity/TileEntity<Name>.java`:
   - поля `private`, изменение только через методы, после изменения — `markDirty()`
   - `writeToNBT` и `readFromNBT`: ключи — константы, чтение через `hasKey(key, Constants.NBT.TAG_…)` со значением по умолчанию; новые ключи не ломают старые миры
   - синхронизация с клиентом, если клиенту нужны данные (рендер, GUI): `getUpdateTag`, `getUpdatePacket`, `onDataPacket`; `world.notifyBlockUpdate` — только при изменении
   - `--tickable`: `implements ITickable`; `if (world.isRemote) return;` для серверной логики, работа раз в N тиков (константа)
   - `--inventory`: `ItemStackHandler` и `hasCapability`/`getCapability` для `CapabilityItemHandler.ITEM_HANDLER_CAPABILITY`, без устаревшего `IInventory`; содержимое выпадает при разрушении блока (`breakBlock`)
   - логика машины (рецепты, прогресс, расчёты) — в `domain/`, TileEntity хранит состояние и вызывает её
2. В блоке — `hasTileEntity(IBlockState)` и `createTileEntity(World, IBlockState)`
3. Регистрация — `GameRegistry.registerTileEntity(TileEntity<Name>.class, new ResourceLocation(MOD_ID, "<имя>"))` в `RegistryEvent.Register<Block>` или в `preInit`, как принято в проекте

## После создания

1. Запусти `lint` профиля из `.aikit/profiles.json` в папке `root` и исправь ошибки
2. Покажи NBT-ключи и что синхронизируется с клиентом
3. Предложи тесты: логика domain и перевод NBT туда и обратно, в том числе без ключа — `$forge-1-12-add-tests`
