## Исполнение в Codex

Задачу и флаги бери из текущего сообщения пользователя. Прочитай `AGENTS.md`, `PRODUCT.md` и `.aikit/profiles.json`, если они относятся к задаче. Для команд профиля используй его `root` и переопределённые `commands`, а не команды, выбранные по названию стека. Пользовательские инструкции имеют приоритет над рекомендациями скилла.

Если шаг требует субагента, используй локальное имя из `.codex/agents/*.toml` без префикса плагина. Предпочитай загруженную именованную роль. Если инструмент не умеет выбирать роль, передай доступному субагенту её `developer_instructions` и нужный контекст; передавай настройки модели только когда это поддерживается схемой инструмента. Не утверждай, что модель из TOML применена, если выбранный способ запуска её не применяет. Если инструменты делегирования недоступны, останови цепочку с объяснением, а не выдавай работу основного потока за запуск агентов.

Независимых тестировщика и ревьюера запускай до ожидания любого из них, затем дождись обоих; исправления передавай уже запущенному агенту доступным инструментом продолжения, если он есть. Лимит параллельности соблюдай. Не создавай пользовательские чаты вместо субагентов. Ключи и параметры запуска инструментов бери из фактической схемы текущей сессии.

Вопросы пользователю задаёт основной поток, а не субагент. Неполный или прерванный результат агента не считай успехом. Модель сама по себе не заменяет запуск проверок: в итог включай реально выполненные команды и их результаты. Операции git выполняй по скиллам `git-branch` и `git-commit`, учитывая режим команды и прямые указания пользователя.

Создай новый предмет мода по правилам проекта (`AGENTS.md`, профиль `forge-1-12-java`).

(задача из сообщения пользователя)

Если имя не указано — запроси его. Имя — registry name в нижнем регистре через `_`. Если не сказано, что предмет делает (материал, инструмент, еда, действие по правому клику), — уточни.

## Перед созданием

- Папка мода — `root` профиля `forge-1-12-java` в `.aikit/profiles.json`
- Найди `ModConstants`, `init/ModItems`, клиентский подписчик моделей и похожие предметы — следуй их стилю
- Проверь, нет ли уже предмета с таким registry name

## Что создать

1. Предмет:
   - простой материал без поведения — экземпляр `Item` в регистрации, отдельный класс не нужен
   - инструмент, броня, еда — от vanilla-класса (`ItemPickaxe`, `ItemArmor`, `ItemFood`) с `ToolMaterial`/`ArmorMaterial` через `EnumHelper`, параметры — константы
   - своё поведение — `item/Item<Name>.java`: `onItemRightClick` возвращает `ActionResult`, мир меняется под `!world.isRemote`, `ItemStack.EMPTY` вместо `null`, NBT стека читается через `hasTagCompound()` и `hasKey`
   - логика сложнее пары строк — в `domain/`
2. Регистрация в `init/ModItems` — `RegistryEvent.Register<Item>`, `setRegistryName`, `setUnlocalizedName` (в маппингах `stable_39` — `setTranslationKey`; бери то, что в проекте), `setCreativeTab`, `@ObjectHolder`
3. Модель — в клиентском `ModelRegistryEvent` через `ModelLoader.setCustomModelResourceLocation`
4. Ключ `item.<modid>.<имя>.name=<Название>` в `assets/<modid>/lang/en_us.lang` (и `ru_ru.lang`, если он есть)

## Ресурсы — не создавай

Модель и текстуру делает не этот профиль. В итоге перечисли:
- `assets/<modid>/models/item/<имя>.json`
- `assets/<modid>/textures/items/<имя>.png`

## После создания

1. Запусти `lint` профиля из `.aikit/profiles.json` в папке `root` (компиляция) и исправь ошибки
2. Покажи созданные и изменённые файлы и список ASSETS_NEEDED
3. Предложи 2-3 тестовых сценария и обновить документацию: `$forge-1-12-mod-docs предметы`
