# Minecraft Plugins — серверные плагины на Java

## Целевая платформа

- Для каждой задачи установи версию Minecraft, ядро, версию API, версию Java на сервере и целевой байткод плагина. Сверь требования задачи, документацию проекта, зависимости и toolchain в Gradle или Maven, а также дескриптор плагина. Если цель неизвестна или сведения противоречат друг другу, перед выбором зависимостей и реализацией платформенного кода уточни цель у пользователя.
- Используй публичный Bukkit/Spigot API целевой версии по умолчанию. Подключай Paper API, если целевой сервер — Paper и задаче нужны его расширения. CatServer проверяй на целевой сборке CatServer, особенно при взаимодействии с Forge-модами и их событиями.
- Для CatServer 1.12.2 с Java 8 используй Spigot API 1.12.2, байткод Java 8 и `plugin.yml` без поля `api-version`. Для Paper 1.20.1 у обычного Bukkit-плагина с API 1.20 указывай `api-version: '1.20'`. Для других версий сверяй допустимое значение и требования к Java с документацией выбранного ядра.
- Ограничь сборку заданной целью. При переносе сверяй изменённые методы и типы API, дескриптор, Java, сторонние зависимости и поведение на новом ядре. Добавляй поддержку нескольких целей только по требованию проекта.
- API сервера подключай как зависимость для компиляции (Gradle `compileOnly` или Maven `provided`). Проверяй, что API сервера не попало в JAR. При необходимости обращения к NMS или CraftBukkit зафиксируй причину и изолируй код, зависящий от версии.

## Код плагина

- Перед правкой прочитай локальные правила и ближайшие рабочие аналоги вне текущего diff. Сверь регистрацию команд и событий, организацию пакетов, обработку ошибок и стиль тестов. Используй существующие компоненты, если они подходят по контракту. Обоснуй новые ветви, состояние и обёртки конкретным требованием или сценарием, который без них нарушится.
- В классе `JavaPlugin` собирай зависимости, регистрируй команды, события и задачи. При выключении освобождай принадлежащие плагину ресурсы и завершай фоновые операции. Логику правил и вычислений держи отдельно от адаптеров сервера.
- Сверяй дескриптор с точкой входа, командами, правами и зависимостями. Проверяй тип отправителя, права, аргументы и конфиг до изменения состояния. Учитывай семантику отмены событий и уже отменённые события.
- Выполняй операции с миром, сущностями и игроками в потоке, который требует API целевого ядра. Выноси блокирующий ввод-вывод из основного потока. Перед использованием результата фоновой операции проверь жизненный цикл плагина и актуальность данных.

## Сборка и проверка

- Запускай команды из `.aikit/profiles.json` в `root` профиля. По умолчанию команды рассчитаны на Gradle Wrapper. Для Maven и нестандартной сборки проект задаёт свои команды.
- Проверяй чистую логику и граничные условия тестами проекта. Команды, права, события, загрузку JAR и межплагинные зависимости проверяй на тестовом сервере целевой версии. Для запуска используй проектную команду `run`, если она настроена. Отдельно укажи, какие проверки реально прошли.
- Если запуск тестов завершился без обнаруженных тестов, укажи это в отчёте. Когда тесты ожидались, проверь их обнаружение и повтори запуск.
