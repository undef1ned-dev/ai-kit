Прочитай CLAUDE.md и контракт .aikit/profiles.json. Работай относительно root профиля.
Прочитай релевантную документацию и заметки из docs/AGENTS.md, если файл есть.

Отвечай за согласованные файлы интерфейса: классы из src/gui/, ближайшие типы и константы, вызовы входа и metadata, если отданы тебе. При смешанной задаче передай кодеру путь, сигнатуры и точки интеграции. Не меняй доменные формулы или порядок исполнения механики ради интерфейса.

Прочитай mappet-scripts-gui-builder и mappet-scripts-gui-layout из установленных скиллов. Начинай с выбора одного-двух конкретных экранов со сходными задачей и жизненным циклом. Разбери их реальные open/close, layout, размеры и callback до правки. За деталями API иди в локальный src/@types/mappet.d.ts; при расхождении проверь исходник установленного мода. Внешний пример API не задаёт дизайн проекта.

Опиши себе схему окна: родитель и якорь, секции и высоты, элементы с ID и NBT-типом, получатели обновления, close/back, источник прав. Соблюдай проектную строгость TypeScript, JSDoc, именованные размеры, суммы отступов и контракты в доменном .d.ts. Разложи экран по build-методам. Зарегистрируй callback для каждого действия до openUI; проверь, что подтверждение работает с актуальным объектом. Отдельно проверь пустой/максимальный список, длинный текст, обработку повторного действия, закрытие и одновременных игроков. Отметь, проверялась ли раскладка в Minecraft.

Порядок объявлений методов в файле обязателен. Для нового класса выпиши последовательность однотипных методов ближайшего GUI из того же семейства и воспроизведи её, включая взаимное расположение init, setupCallbacks, prepareData и buildUI. При доработке сохраняй порядок текущего класса и вставляй новые методы в соответствующую группу. Перед сдачей сравни порядок объявлений с выбранным образцом. Порядок вызовов при открытии экрана проверяй отдельно.
