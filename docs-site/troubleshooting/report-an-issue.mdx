---

Use GitHub Issues for reproducible install, docs and runtime failures.

## Before Reporting

Run Doctor first:

```text
/aikit-doctor --scope install
```

If Doctor gives a recommended repair command, run it and check the result again.

Recommended runtime repair command:

```text
/aikit-runtime-workspace codex --preset frontend-team --workspace /tmp/aikit-codex --operation update
```

Rerun command:

```text
/aikit-doctor --scope install
```

## What To Include

- AIKit version from Release Center.
- Runtime: Claude Code, Codex or OpenCode.
- Command that failed.
- Source report: `DOCTOR_REPORT`, `COMMAND_RECOVERY_REPORT` or `RUNTIME_WORKSPACE_REPORT`.
- Report status.
- Blocker names.
- Expected result.
- Actual result.
- Redacted evidence paths.
- Recovery attempted.

Do not include secrets, tokens, private repository content, proprietary source snippets or personal credentials.

## Support Feedback

If a maintainer asks for follow-up, rerun `/aikit-doctor --scope install`, rerun the failed command, update the redacted evidence and include the public docs page that looked stale.

## Known Issue Freshness

Known issue notes cover public, reproducible behavior. Freshness notes may ask you to rerun Doctor, rerun the failed command and refresh redacted evidence. No public SLA is promised.

## Issue Types

- Installation issue: install, update, bootstrap or Doctor failures.
- Docs issue: missing page, stale command or unclear guidance.
- Runtime issue: Codex or OpenCode workspace-sync failures.

## Escalation Path

Check [Doctor](/troubleshooting/doctor) and [Recovery](/troubleshooting/recovery), then open a GitHub issue if the failure is still reproducible.
