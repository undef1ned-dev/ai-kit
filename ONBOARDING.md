# Онбординг: Claude Code с AIKit

> Этот документ относится именно к Claude Code adapter.
> Общая multi-runtime архитектура описана в [docs/multi-runtime-architecture.md](docs/multi-runtime-architecture.md).

Это руководство для тех, кто впервые работает с Claude Code и агентами.
Прочитай от начала до конца — займёт около 15 минут.

---

## Что такое Claude Code?

Claude Code — это AI-ассистент который работает прямо в терминале, видит весь твой проект и может писать, редактировать и анализировать код. В отличие от чата в браузере, он:

- **Читает файлы** — знает структуру проекта, существующий код, конфигурацию
- **Пишет файлы** — создаёт и редактирует реальные файлы в проекте
- **Запускает команды** — может собирать, тестировать, делать git-операции
- **Помнит контекст** — в рамках сессии помнит всё что ты ему говорил

Ключевая идея: **ты общаешься с ним как с разработчиком**, а не как с поисковиком. Не ищи ответы — ставь задачи.

## Часть 1. Установка и первый запуск

### Требования
- macOS / Linux
- Node.js 18+
- Git

### Установка

```bash
# 1. Установи Claude Code
npm install -g @anthropic-ai/claude-code

# 2. Проверь установку
claude --version

# 3. Авторизуйся (откроет браузер)
claude
```

При первом запуске Claude откроет браузер для авторизации через аккаунт Anthropic. После — вернётся в терминал.

### Первый запуск в проекте

```bash
cd твой-проект
claude
```

Откроется интерактивный режим. Ты видишь строку ввода — просто пиши задачи на русском языке.

Для выхода: `Ctrl+C` или напиши `/exit`

## Часть 2. Подключение AIKit к проекту

Один раз при начале работы с репозиторием:

```bash
cd твой-проект

# Добавить конфиги как git submodule
git submodule add git@github.com:undef1ned-dev/ai-kit.git .aikit-config
git submodule update --init

# Применить профиль (выбери нужный)
bash .aikit-config/scripts/attach.sh vue-nuxt
# или
bash .aikit-config/scripts/attach.sh python-django
```

Скрипт создаст в проекте:
```
CLAUDE.md          ← правила для Claude (не удалять!)
PRODUCT.md         ← заполни информацию о продукте (опционально)
.claude/
  settings.json    ← MCP серверы (в .gitignore, не шарится)
  commands/        ← /команды
  agents/          ← специализированные агенты
  memory/          ← память проекта (в git, шарится между разработчиками)
    INDEX.md       ← индекс: решения, паттерны, коррекции
    decisions/     ← архитектурные решения
    patterns/      ← паттерны кода
    corrections/   ← коррекции поведения агентов
    tasks/         ← логи задач (archive/ для старых)
    features/      ← feature-scope память
```

> **Память накапливается автоматически.** После каждой значимой задачи запускай
> `/capture-memory` — агент `memory-writer` зафиксирует контекст и откроет MR.
> `.claude/memory/` коммитится в git и шарится между всей командой.

### Клонирование проекта который уже использует AIKit

```bash
git clone <url-проекта>
cd проект
git submodule update --init    # подтянуть .aikit-config
bash .aikit-config/scripts/attach.sh <профиль>
```

## Часть 3. Базовые понятия

### CLAUDE.md — "правила игры"

Файл `CLAUDE.md` в корне проекта — это инструкция которую Claude читает при каждом запуске. Там написано:
- Какой стек используется
- Как называть файлы и классы
- Что запрещено
- Как организована архитектура

Ты его не правишь руками — он генерируется из профиля. Если нужно добавить правило специфичное для проекта — добавляй в конец файла.

### Скиллы (Skills) — `/команды`

Скиллы — это готовые "рецепты" для типовых задач. Вызываются через `/`.

```
/implement-feature Список уведомлений
/analyze-mvp Добавить биометрическую авторизацию
```

Думай о них как о макросах: одна команда запускает сложный сценарий.

**Как посмотреть доступные скиллы:**
```
/help
```

### Агенты — специализированные роли

Агенты — это Claude настроенный на конкретную роль. Когда ты говоришь "используй vue-architect", Claude берёт системный промпт этого агента и работает как архитектор Vue/Nuxt-фич: читает проект, проектирует структуру, выдаёт план в конкретном формате.

**Агентов вызывают двумя способами:**

1. **Через скилл** — `/implement-feature` сам запустит нужных агентов по цепочке
2. **Напрямую** — "Используй агент `vue-reviewer` чтобы проверить вот эти файлы"

## Часть 4. Как правильно ставить задачи

Это самое важное. Качество результата на 80% зависит от того, как ты формулируешь задачу.

### Правило №1: Давай контекст, не просто команду

```
❌ Плохо:
"Добавь кнопку"

✅ Хорошо:
"На странице pages/profile.vue добавь кнопку 'Выйти' в правый верхний угол.
При нажатии должен вызываться метод logout() из useAuthStore."
```

### Правило №2: Говори что нужно получить, не как это сделать

```
❌ Плохо:
"Создай файл ProfileHeader.vue с компонентом, который содержит..."

✅ Хорошо:
"Пользователь должен видеть свой профиль: аватар, имя, email.
При нажатии на аватар — открывается выбор фото."
```

Claude сам решит как это реализовать согласно правилам команды.

### Правило №3: Для большой задачи — используй скилл или цепочку агентов

```
❌ Плохо (всё в одном):
"Сделай полноценный экран уведомлений с API, тестами и ревью"

✅ Хорошо:
/implement-feature Экран уведомлений: список push-уведомлений,
отметить как прочитанное, удалить, badge на иконке таб-бара
```

### Правило №4: Уточняй при необходимости

Если агент спросил уточняющий вопрос или выдал вопросы в `QUESTIONS` — ответь на них. Это нормально и улучшает результат.

### Правило №5: Проверяй результат

После каждого шага смотри что создано. Если что-то не так — говори конкретно:

```
"В созданном NotificationsView нет обработки пустого состояния.
Добавь ContentUnavailableView когда список уведомлений пустой."
```

## Часть 5. Типовые рабочие сценарии

### Сценарий А: Новая фича с нуля

```
Шаг 1: Убедись что PRODUCT.md заполнен

Шаг 2: Запусти реализацию
/implement-feature <описание фичи>

Шаг 3: Дождись работы агентов:
  vue-architect → проектирует структуру
  vue-coder     → пишет код
  vue-tester    → пишет тесты    (параллельно)
  vue-reviewer  → проверяет код  (параллельно)

Шаг 4: Прочитай замечания ревьюера, исправь если нужно

Шаг 5: Создай MR
```

### Сценарий Б: Небольшое изменение

Для маленьких изменений агенты не нужны — просто описывай задачу:

```
"В файле pages/profile.vue замени стандартный спиннер
на наш BaseLoader из components/base"
```

### Сценарий В: Проверка кода перед MR

```
"Используй агент vue-reviewer чтобы проверить изменения в ветке.
Файлы: components/feature/NotificationsPanel.vue,
       composables/useNotifications.ts"
```

### Сценарий Г: Анализ идеи перед разработкой

```
/analyze-mvp Добавить систему достижений: пользователь получает
бейджи за определённые действия в приложении. Показываем в профиле.
```

Агент `mvp-analyst` создаст документ `docs/mvp/sistema-dostizheniy.md` с анализом объёма, рисков и оценкой.

### Сценарий Д: Написать тесты для существующего кода

```
"Используй агент vue-tester чтобы написать тесты для
composables/useAuth.ts"
```

### Сценарий Е: Зафиксировать память после задачи

После завершения значимой задачи:

```
/capture-memory
```

Агент `memory-writer` задаст уточняющие вопросы (или извлечёт контекст из истории),
создаст файлы в `.claude/memory/` и откроет MR на ревью команде.

Проверить состояние памяти:
```
/memory-status
```

## Часть 6. Полезные команды Claude Code

Прямо в интерактивном режиме (`claude`):

| Команда | Что делает |
|---------|-----------|
| `/help` | Список доступных скиллов |
| `/clear` | Очистить историю сессии |
| `/compact` | Сжать историю (освободить контекст) |
| `Ctrl+C` | Прервать текущее действие |
| `Ctrl+L` | Очистить экран |

Из терминала (вне интерактивного режима):

```bash
# Одиночный вопрос без открытия сессии
claude "Что делает файл composables/useAuth.ts?"

# Передать файл
claude "Проверь этот файл" --file pages/profile.vue
```

## Часть 7. Что делать если что-то пошло не так

**Claude делает что-то не то:**
Прервёт Ctrl+C и объясни точнее: "Стоп. Я имею в виду не X, а Y"

**Агент не находит файлы:**
Убедись что ты запустил `claude` из корня проекта.

**Скилл не работает:**
Проверь что профиль подключён: `ls .claude/skills/` — должны быть `.md` файлы.

**Нужно обновить конфиги из AIKit:**
```bash
bash .aikit-config/scripts/update.sh
bash .aikit-config/scripts/attach.sh <профиль>
```

**Агент выдал что-то странное:**
Это бывает. Попроси пересмотреть:
"Это не соответствует нашим правилам из CLAUDE.md. Пожалуйста пересмотри решение."

## Часть 8. Dos and Don'ts

### Делай ✅

- Используй `/implement-feature` для больших фич — это экономит время
- После значимых задач запускай `/capture-memory` — накапливай контекст команды
- Давай конкретный контекст в задачах
- Проверяй результат перед коммитом
- Спрашивай агента если что-то непонятно в созданном коде

### Не делай ❌

- Не давай агентам права на force push или удаление файлов
- Не коммить `.claude/settings.json` — там могут быть локальные пути
- Не добавляй `.claude/memory/` в `.gitignore` — память должна шариться между разработчиками
- Не меняй `CLAUDE.md` вручную если хочешь сохранить изменения — правки потеряются при следующем `attach.sh`
- Не запускай `claude` вне корня проекта — агенты не найдут файлы
