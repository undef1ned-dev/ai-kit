Roadmap AIKit

Цель — универсальный кит, который одинаково подключается к проектам на любом стеке:

  • чистый фронтенд на Nuxt;
  • fullstack Nuxt + Node.js;
  • Java-проект (моды);
  • любой другой стек — через новый профиль, без правок ядра.

Поэтому сначала делаем общее: формат поставки, контракт профиля, хуки, общие workflow и память. Частное — настройку конкретных агентов и профилей — делаем в конце, поверх готового ядра.

#Принцип: один кит — несколько runtime

Кит должен одинаково работать в разных AI-агентах:

RuntimeПриоритет
Claude Codeосновной
Codex (CLI / Desktop / IDE)основной, наравне с Claude Code
OpenCodeподдерживаемый — переносим всё, что позволяет runtime

Адаптер GLM удалён: GLM — модель, а не отдельный агент, её можно запускать через любой из runtime выше.

Правила:

  1. Источник один. Агенты, скиллы, правила, MCP-серверы и хуки описываются один раз в base/, profiles/, packs/. Под каждый runtime они раскладываются установщиком в его родной формат (CLAUDE.md / AGENTS.md, .claude/skills/ / .agents/skills/, .mcp.json / .codex/config.toml / opencode.json и т.д.).
  2. Каждая задача roadmap делается для всех runtime, а не только для Claude Code. Задача не закрыта, пока не сделана для Claude Code и Codex; для OpenCode — сделана или явно отмечена как невозможная.
  3. Расхождения документируются. Если в каком-то runtime функцию нельзя сделать или она работает иначе — это фиксируется в матрице docs/runtime-support.md: что есть, чего нет, чем заменить.
  4. Smoke-тест проверяет все runtime, а не только attach.sh.

Источники: аудит после чистки репозитория и исследование модернизации (разделы 4–6).

#Этап 4. Хуки — правила, которые соблюдаются всегда ✅

Все хуки — общие; стековая часть (какой линтер запускать) берётся из контракта профиля.

Логика хука — один скрипт (Python или bash), который вызывают все runtime:

  • Claude Code — hooks в .claude/settings.json;
  • Codex — .codex/hooks.json почти того же формата (те же события PreToolUse, PostToolUse, Stop, SessionStart); хуки нужно один раз одобрить через /hooks;
  • OpenCode — тонкий JS-плагин в .opencode/plugins/ (tool.execute.before / after, session.idle), который вызывает тот же скрипт.

4.1 ✅PreToolUseБлокирует запись секретов, .env, git add .env
4.2 ✅PreToolUse (git commit)Сообщение по Conventional Commits, без Co-Authored-By
4.3 ✅PreToolUse (git checkout -b / switch -c)Имя ветки по Conventional Branch
4.4 ✅PostToolUse (Edit/Write)Запускает format / lint из контракта профиля для изменённого файла
4.5 ✅StopЕсли менялся код — запустить test из контракта или напомнить; после крупной задачи предложить /capture-memory
4.6 ✅SessionStartПодгружает .aikit/memory/INDEX.md и PRODUCT.md

Сделано: логика всех хуков — base/hooks/aikit_hook.py (без зависимостей), установщики копируют его в .aikit/hooks/ и подключают через scripts/hooks_config.py: hooks в .claude/settings.json, .codex/hooks.json, плагин .opencode/plugins/aikit-hooks.js; хуки пользователя при обновлении сохраняются. Какие файлы считаются кодом профиля, задаёт новое необязательное поле контракта code_extensions. Если инструмента профиля нет, хук пропускает линтер и напоминает о тестах вместо блокировки. В OpenCode память подключается через instructions в opencode.json. Сценарии хуков — scripts/ci/test-hooks.py в статических проверках, smoke-тесты проверяют подключение во всех runtime. Ручная проверка в живых Codex и OpenCode — вместе с прогоном /implement-feature (этапы 3 и 5).
