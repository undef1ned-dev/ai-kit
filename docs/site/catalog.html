Агенты 13

🤖agent-builder

Создаёт нового агента через структурированный опрос по 6 фазам. Генерирует готовый .md файл с чёткой ролью, алгоритмом, правилами и форматом вывода. Используй когда нужно добавить нового специализированного агента в репозиторий.

→ AGENT_FILEsonnet
Создай агента для проверки локализации
base/agents/agent-builder.md
🤖aikit-maintainer

Хранитель и развиватель репозитория AIKit. Улучшает агентов, skills, manifests, routing, memory и документацию, не ломая консистентность системы. Обязан обновлять memory самого репозитория и прогонять обязательную матрицу проверок.

→ AIKIT_MAINTENANCE_REPORTsonnet
Улучши routing policy для multi-profile задач и обнови документацию
base/agents/aikit-maintainer.md
🤖cross-project-analyst

Кросс-проектный аналитик. Анализирует влияние изменений между backend и iOS — когда меняется API, определяет что нужно обновить на другой стороне. Помогает с координацией.

→ CROSS_CHECK_REPORTsonnet
Изменился endpoint /api/v1/profile — что нужно обновить в iOS?
base/agents/cross-project-analyst.md
🤖memory-optimizer

Консолидирует canonical память проекта. Архивирует старые задачи, сжимает INDEX до 60 строк, мержит дублирующиеся паттерны и затем синхронизирует Claude mirror. Запускай через /optimize-memory когда /memory-status показывает предупреждение.

sonnet
base/agents/memory-optimizer.md
🤖memory-writer

Фиксирует контекст после завершённой задачи. Пишет в canonical .aikit/memory/ и поддерживает .claude/memory/ как mirror для совместимости. Используй через /capture-memory после завершения работы.

sonnet
base/agents/memory-writer.md
🤖mvp-analyst

MVP-аналитик уровня зрелого продукта. Принимает описание идеи и формирует структурированный анализ в docs/mvp/. Учитывает бизнес-кейс, существующую аудиторию, конкурентный контекст, rollout-стратегию и операционную готовность. Читает PRODUCT.md для контекста продукта.

→ MVP_ANALYSISsonnet
Проанализируй идею: добавить экспорт отчётов в PDF
base/agents/mvp-analyst.md
🤖platform-evangelist

Продуктовый стратег и евангелист AIKit. Упаковывает платформу в понятную историю для команды: позиционирование, onboarding, adoption paths, MCP/RAG narrative, runtime value и product-facing surfaces.

→ PLATFORM_GROWTH_PLANsonnet
Сформируй product plan для развития AIKit как MCP + RAG platform
base/agents/platform-evangelist.md
🤖release-manager

Релиз-менеджер. Собирает changelog из коммитов, генерирует release notes для App Store / внутренней рассылки, проверяет готовность к релизу.

🤖security-auditor

Создаёт новый скилл через структурированный опрос по 4 фазам. Генерирует папку <name>/SKILL.md с оркестрацией агентов и чётким форматом вывода. Используй когда нужно добавить новый скилл в репозиторий.

Технический планировщик. Читает продуктовый MVP-документ и переводит его в технический план реализации по платформам. Определяет API-контракт, scope каждой платформы, порядок реализации. Используй после mvp-analyst, перед архитекторами.

🤖ux-writer

UX-копирайтер. Пишет и ревьюит тексты интерфейса — кнопки, ошибки, пустые состояния, онбординг, push-уведомления. Следит за консистентностью терминологии.

→ UX_TEXTSsonnet
Напиши тексты для экрана онбординга

🤖workflow-runner

Оркестратор рабочих процессов. Читает манифесты агентов, строит цепочку по depends_on, проводит разработчика через каждый шаг с передачей контекста. Используй через skill `workflow` или напрямую как custom agent `workflow-runner`.

⚡/git-branch

Convention for naming git branches in this repository: Conventional Branch 1.1.0. MUST be followed whenever a branch is created or renamed — always, automatically, without the user having to ask. Trigger whenever you are about to run `git checkout -b`, `git switch -c`, `git branch <name>`, `git branch -m`, create a worktree with a new branch, or when the user says «создай ветку», «новая ветка», «branch», «переименуй ветку». Defines branch types, naming rules and which base branch to start from.

base/skills/git-branch/SKILL.md
⚡/git-commit

Convention for writing git commit messages in this repository: Conventional Commits 1.0.0. MUST be followed for every commit created in the project — always, automatically, without the user having to ask. Trigger whenever you are about to run `git commit` (including amend, squash or rewriting history), or when the user says «закоммить», «коммит», «сделай коммит», «commit», or asks to save/commit changes. Also forbids any co-authorship trailers.

base/skills/git-commit/SKILL.md
