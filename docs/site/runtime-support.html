Поддержка runtime

Какие возможности AIKit работают в каждом AI-агенте, где отличия и чего нет. Обновляется в каждой задаче roadmap, которая добавляет или меняет функционал (см. принцип в roadmap.md).

Приоритет: Claude Code и Codex — основные, OpenCode — переносим всё, что позволяет runtime.

GLM отдельно не поддерживается: это модель, а не агент — её можно запускать через любой из этих runtime, и кит будет работать так же, как в нём.

Обозначения:

  • ✅ работает;
  • ⚠️ работает частично или иначе — см. примечание;
  • ❌ не сделано в AIKit, хотя runtime умеет — задача в roadmap;
  • 🚫 runtime этого не умеет — нужна замена или функция недоступна;

#3. Известные ограничения

Функции, которые в каком-то runtime нельзя сделать так же, как в Claude Code, и чем они заменены.

ФункцияRuntimeОграничениеЗамена
Slash-командыCodexПроектных slash-команд нет (глобальные ~/.codex/prompts устарели и общие для всех проектов — кит их не пишет)Скиллы: $name или автовызов
Агенты из проектаCodex.codex/agents/ применяется только в доверенных проектахВ инструкции .codex/AIKIT.md — шаг «отметить проект доверенным»
Правила и скиллыCodex, OpenCodeТексты написаны в синтаксисе Claude Code (/name, местами .claude/)В начале блока AIKit в AGENTS.md объяснено, что /name — это скилл ($name в Codex); пути .claude/agents/ и .claude/skills/ в скиллах заменяются на пути runtime
$ARGUMENTS в скиллахCodex, OpenCodeНе подставляетсяПри установке заменяется на «(задача из запроса пользователя)»
Запрет автовызова скиллаOpenCodeНет поля в SKILL.mdПока нет; скиллы с побочными эффектами сами просят подтверждения
MCP из проектаCodex.codex/config.toml применяется только в доверенных проектахВ .codex/AIKIT.md — шаг «отметить проект доверенным»
