# Поддержка runtime

Какие возможности AIKit работают в каждом AI-агенте, где отличия и чего нет.
Обновляется в каждой задаче roadmap, которая добавляет или меняет функционал (см. принцип в [roadmap.md](roadmap.md)).

Приоритет: **Claude Code** и **Codex** — основные, **Antigravity** и **OpenCode** — переносим всё, что позволяет runtime.

GLM отдельно не поддерживается: это модель, а не агент — её можно запускать через любой из этих runtime, и кит будет работать так же, как в нём.

Обозначения:

- ✅ работает;
- ⚠️ работает частично или иначе — см. примечание;
- ❌ не сделано в AIKit, хотя runtime умеет — задача в roadmap;
- 🚫 runtime этого не умеет — нужна замена или функция недоступна;

## 1. Что умеет каждый runtime

Codex имеет самостоятельные источники агентов и скиллов в `<слой>/codex/`. Общими остаются RULES.md, контракты, память и MCP. Antigravity и OpenCode используют конвертацию Markdown со своими правилами `adapters/<runtime>/rules.md` и нативными хуками.

Справочник по родным механизмам. Сверено с документацией 2026-10-12, плагины — 2026-10-31.

| Возможность | Claude Code | Codex | Antigravity | OpenCode |
|---|---|---|---|---|
| Правила проекта | `CLAUDE.md` | `AGENTS.md` | `AGENTS.md` и `.agents/rules/*.md` | `AGENTS.md` (если его нет — `CLAUDE.md`) |
| Скиллы `<name>/SKILL.md` | `.claude/skills/` | `.agents/skills/` | `.agents/skills/` и `skills/` в плагине | `.opencode/skills/`, а также `.claude/skills/` и `.agents/skills/` |
| Вызов скилла | `/name` или автоматически по `description` | `$name`, `/skills` или автоматически по `description` | `/name` или автоматически по `description` | автоматически по `description` |
| Запрет автовызова скилла | `disable-model-invocation: true` во frontmatter | `policy.allow_implicit_invocation: false` в `<skill>/agents/openai.yaml` | нет в самом скилле | нет в самом скилле (только `permission` в `opencode.json`) |

Версия плагинов. В `.claude-plugin/plugin.json`, `.codex-plugin/plugin.json` и записях маркетплейса стоит `version` — она равна файлу `VERSION` кита, её пишет `scripts/build-plugins.py`. Как с ней работает Codex (проверено по исходникам openai/codex):

- без `version` плагин ложится в кэш как `local` и сам никогда не обновляется — только вручную, `codex plugin marketplace upgrade`;
- с `version` кэш ведётся по версии, и при смене номера плагин обновляется автоматически;
- версия — непустая строка из ASCII-букв, цифр и `.`, `+`, `_`, `-`; semver (`0.2.0`) подходит.

## 3. Известные ограничения

Диагностика Codex: `$aikit:setup --check` или `python3 .aikit/scripts/codex-doctor.py --workspace .` при установке адаптером (Python 3.11+). Проверяет конфигурацию и историю, не меняет проект и не запускает модель или MCP-серверы. Отдельно показывает `unknown` для одобрения текущей версии хуков; доверие из файла и наличие MCP не доказывают готовность активной сессии или соединения. История хранится по runtime, отметки старше суток и старого общего формата не принимаются за подтверждение. Автоматический режим `setup --check` в Claude пока не реализован; обычный setup Claude сохраняет прежнюю проверку.

Функции, которые в каком-то runtime нельзя сделать так же, как в Claude Code, и чем они заменены.

| Функция | Runtime | Ограничение | Замена |
|---|---|---|---|
| Slash-команды | Codex | Проектных slash-команд нет (глобальные `~/.codex/prompts` устарели и общие для всех проектов — кит их не пишет) | Скиллы: `$name` или автовызов |
| Агенты из проекта | Codex | `.codex/agents/` применяется только в доверенных проектах | В инструкции `.codex/AIKIT.md` — шаг «отметить проект доверенным» |

| Хуки | Codex | На Windows команда хука (`commandWindows`) идёт через `powershell -NoProfile -Command` или `cmd.exe`: `${VAR}` и `$(...)` не работают, а Windows PowerShell 5.1 превращает код выхода 2 в 1 — блокировка выглядит как сбой хука | Лаунчер `python -c` без синтаксиса shell ищет скрипт от cwd вверх (адаптер) или берёт `PLUGIN_ROOT` из окружения (плагин); блокировка — JSON `permissionDecision: deny` с кодом 0 (`--deny-json`). Лаунчер переживает Python 2 и старый Python 3 в PATH: передаёт событие `py -3` или `python3` 3.9+. Заглушка Microsoft Store вместо `python` его не запускает |
| Хуки на Windows | Codex | Хуки AIKit работают в живой сессии (CLI 0.163), если `python` в окружении хука — Python 3.9+; с заглушкой Microsoft Store они падают с кодом 1 и молча не защищают. Установка, одобрение и выполнение — разные состояния | Лаунчер передаёт событие `py -3`/`python3`, если `python` старый; `/aikit:setup` читает отметки запусков (`aikit_hook.py --status`).
