# Команды

Все скиллы ядра — они есть в любом проекте с AIKit, какие бы профили ни стояли. Скиллы профилей и паков описаны в [каталоге](../site/catalog.html).

## Как вызывать

| Runtime | Явный вызов | Список скиллов | Автовызов |
|---|---|---|---|
| Claude Code | `/implement-feature <задача>` | набери `/` | да, по `description` скилла |
| Codex | `$implement-feature <задача>` | `/skills` | да |
| OpenCode | назови скилл в сообщении | — | да |

Если кит стоит плагинами, у скилла есть и имя с префиксом плагина: `/aikit:implement-feature`, `/vue-nuxt:new-page`. Короткое `/implement-feature` работает, пока имя не занято другим скиллом.

**Автовызов** значит, что runtime сам запустит скилл, если задача подходит под его описание. Например, на «реализуй страницу заказов» может сработать `/implement-feature`. Скиллы с пометкой «только явный вызов» сами не запускаются: у них есть побочные эффекты (пишут память, ведут длинный диалог).

## Панель AIKit Deck

Только Claude Code с установкой плагинами: панель — мод плагина ядра `aikit`. При старте сессии она открывается сама в проекте с `.aikit/profiles.json`, в папке с одним `.aikit/settings.json` (так в репозитории кита) и там, где панель уже открывали; иначе — командой `/deck`. Сама по себе панель встаёт только в достаточно широком окне терминала (около 144 колонок, 110 — если ты её уже открывал). В более узком окне Claude Code ждёт твоего действия, причина пишется в debug-лог. На это время над полем ввода, где Claude Code показывает опросы, появляется строка «AIKit Deck» с кнопкой «Открыть»: она есть с начала сессии, ещё до первого сообщения, и открывает панель при любой ширине. Когда панель открыта, идёт опрос или строку занял другой мод, панель эту строку не трогает. Пока панель закрыта, в строке под полем ввода, рядом с подписями режимов, видна кнопка «AIKit Deck»: она открывает панель и во время работы ассистента, когда команда ждала бы конца ответа. Кнопка есть в подключённом проекте и там, где панель уже открывали. В неподключённом проекте панель показывает базовые команды, субагентов и справку; команды профиля появятся после `/aikit:setup`.

| Что в панели | Как работает |
|---|---|
| Кнопки команд | Базовые команды кита по группам, ниже — команды профилей и паков проекта, в конце — свои скиллы проекта из `.claude/skills/` (группа «Скиллы проекта»; копии скиллов кита, оставшиеся от `attach.sh`, не повторяются). Скиллы только для Codex (`update-agents`) в панели не показываются. В репозитории кита в группе «Кит» есть `/improve-aikit`. Команде с аргументом открывается поле ввода (подсказка — `argument-hint` скилла), флаги вроде `--tdd` — переключатели. Обязательное поле пустым не отправится |
| Действия проекта | Блок над командами в подключённом проекте: кнопки из `actions` профилей в `.aikit/profiles.json` (у `forge-1-12-java` — «Компиляция», «Тесты», «Сборка», «Клиент», «Сервер», то есть `./gradlew compileJava`, `test`, `build`, `runClient`, `runServer`) и у каждого профиля — «Обновить профиль» (`claude plugin marketplace update aikit`, затем `claude plugin update <профиль>@aikit` для каждой установленной записи плагина в этом проекте: `--scope user`, `--scope project`, `--scope local`). Под кнопкой — команда, которая запустится. Команда выполняется на этой машине в папке профиля, без модели и без shell; на Windows — через `cmd /d /c`, `./gradlew` — как `.\gradlew.bat` (программы из `PATH`, например `claude`, — по имени). В карточке — статус («работает», «завершено, код N»), ниже — последние строки вывода, у работающей — «Стоп». Результат «Обновить профиль» — всплывающим сообщением, а не в блоке вывода: версии до и после («0.6.0 → 0.7.0»), «уже последняя версия» или код ошибки с последней строкой вывода; пока обновление идёт, карточка показывает «работает». Пока действие работает, второй раз оно не запустится. Свои кнопки команда добавляет в `actions` того же файла — обновление кита правку сохранит ([контракт профиля](adding-a-stack.md#что-такое-контракт-профиля)) |
| Версии | В шапке — версия кита, которую выполняет сессия (`version` из `.claude-plugin/plugin.json` плагина ядра), и рядом с каждым профилем и паком — версия его плагина, установленная для этого проекта (`installed_plugins.json` Claude Code: запись проекта сильнее записи пользователя). Версии читаются при старте сессии и после обновления кнопкой не меняются, пока сессия не перезапущена. Если версию узнать нельзя (плагин ядра загружен через `--plugin-dir`, записи нет), показывается только имя |
| Обновить кит | Кнопка на отдельной строке шапки, рядом с версией кита: `claude plugin marketplace update aikit` и `claude plugin update aikit@aikit` — то же, что `/plugin marketplace update aikit` и `/plugin update aikit@aikit`. Если кит установлен в нескольких scope (для пользователя и для проекта), обновляются все записи для этого проекта — `--scope user`, `--scope project`, `--scope local`; записи других проектов и `managed` не трогаются ([почему](known-issues.md#плагин-обновился-а-версия-осталась-прежней)). Результат — всплывающим сообщением с версиями до и после или с ошибкой и scope, где она случилась; новая версия подхватится после перезапуска сессии |
| Режим | «Отправить» (по умолчанию) — команда сразу уходит в сессию; «Вставить» — попадает в поле ввода, Enter жмёшь сам. Клавиша `m` |
| Коммит без вопроса | Переключает [режим коммитов](#коммиты-с-вопросом-или-без) проекта в `.aikit/settings.json`. Есть в подключённом проекте и там, где лежит `.aikit/settings.json` без профилей (так в репозитории кита). Клавиша `c` |
| Субагенты | Все субагенты сессии — запущенные из чата, скиллом или панелью: тип, задача, модель, время, статус. Список даёт сам Claude Code; модель — та, что ответила на последний запрос субагента (появляется после его первого запроса) |
| Справка | Вкладка `2`: все команды с аргументами, описанием и примером, поиск по имени и описанию |
| История | Последние запуски из панели и команды кита, набранные в чате. Строка истории открывает команду снова с тем же текстом |
| Память | Размер `.aikit/memory/INDEX.md` в шапке; больше 50 строк из 60 — строка «пора `/optimize-memory`» под полем ввода, даже при закрытой панели |

Панель не вызывает модель: кнопки, справка, субагенты и память — локальные файлы и данные Claude Code, действия проекта и обновление — программы на машине. Лимиты тратит только запущенная команда кита — ровно как набранная вручную.

## Разработка

| Команда | Что делает | Агенты |
|---|---|---|
| `/implement-feature` | Реализует фичу цепочкой агентов профиля: архитектор → кодер → тестировщик и ревьюер параллельно → проверка `lint`/`test`, исправления и проверка в работе. Флаги: `--tdd` — сначала падающие тесты, `--worktree` — работа в отдельном git worktree, `--no-test` и `--no-review` — без тестировщика и без ревьюера, для быстрых правок с экономией токенов (можно вместе) | агенты профиля по ролям |
| `/fix-bug` | Чинит баг: воспроизведение → тест, который ловит баг → минимальный фикс → `lint`, `test` и ревью. Флаги `--no-test` и `--no-review` — без теста на баг и без ревьюера (можно вместе) | агенты профиля по ролям |
| `/check-feature` | Запускает приложение командой `run` и проходит сценарий фичи: в браузере для UI, запросами для API; сообщает, работает ли | — |

## Анализ и планирование

| Команда | Что делает | Агенты |
|---|---|---|
| `/analyze-mvp` | Разбирает идею фичи: интервью, варианты, бизнес-кейс, риски, RICE; результат — документ в `docs/mvp/` | `mvp-analyst` |
| `/implement-mvp` | Превращает MVP-документ в технический план: API-контракт, scope по частям системы, порядок работ | `tech-planner` |
| `/cross-check` | Что поменять на другой стороне, если меняется API или формат данных | `cross-project-analyst` |

## Качество и безопасность

| Команда | Что делает | Агенты |
|---|---|---|
| `/security-check` | Аудит безопасности: OWASP Top 10, секреты в коде и конфигах, авторизация, инъекции | `security-auditor` и security-специалист профиля (`specialists.security`), если он есть |
| `/coverage-check` | Запускает тесты с покрытием, находит критичные модули без тестов и предлагает тест-кейсы | quality-специалист профиля (`specialists.quality`) |
| `/tech-debt` | Аудит технического долга: большие модули, дублирование, нарушения слоёв, TODO; backlog P1/P2/P3 | quality-специалист профиля (`specialists.quality`) |
| `/write-ui-texts` | Пишет или проверяет тексты интерфейса: кнопки, ошибки, пустые состояния, онбординг | `ux-writer` |

## Память проекта

| Команда | Что делает | Агенты |
|---|---|---|
| `/capture-memory` | Записывает решения, паттерны и поправки агентам после задачи в `.aikit/memory/`: показывает, что понял из разговора, и после подтверждения спрашивает, как сохранить — в рабочей папке, коммитом или PR. Только явный вызов | `memory-writer` |
| `/memory-status` | Показывает, что накоплено в памяти и не пора ли её сжать | — |
| `/optimize-memory` | Сжимает индекс памяти, объединяет дубли, убирает устаревшее; переносит решения из логов задач прежних версий; логи и личные записи удаляет только с согласия. Только явный вызов | `memory-optimizer` |

## Расширение кита

| Команда | Что делает | Агенты |
|---|---|---|
| `/create-agent` | Создаёт нового агента через интервью из 6 фаз. В репозитории кита — агента кита в `base/`, профиле или паке; в проекте — локального агента только для этого проекта: Claude Code — `.claude/agents/<имя>.md`, Codex — `.codex/agents/<имя>.toml`, OpenCode — `.opencode/agents/<имя>.md` | `agent-builder` |
| `/create-skill` | Создаёт новый скилл через интервью из 4 фаз. В ките — скилл кита; в проекте — локальный: Claude Code — `.claude/skills/<имя>/`, Codex — `.agents/skills/<имя>/`, OpenCode — `.opencode/skills/<имя>/` | `skill-builder` |
| `/set-model` | Показывает модели агентов или меняет модель агента в проекте: уровень (`opus`, `sonnet`, `haiku`) или конкретная модель для Claude Code, Codex, OpenCode. Пишет `.aikit/models.json` — общий для команды. Уровень усилий в Claude Code (`effort`: архитекторы `high`, остальные `medium`) задан в самих агентах и при смене модели не меняется. Только явный вызов | — |
| `/aikit:setup` | Подключает проект к киту, установленному плагинами: профили и паки, блок правил, `.aikit/profiles.json`, память, настройки. Есть только в плагине ядра | — |
| `/aikit:update-agents` | Только Codex, явный вызов: `$aikit:update-agents --with-plugins` обновляет маркетплейс `aikit`, проверяет версии и пересобирает агенты из свежего источника одной командой. Без флага — только пересборка агентов после ручного обновления плагинов. Правила, контракты, память, свои агенты и настройки команды сохраняются. Есть только в плагине ядра | — |

Режим `/create-agent` и `/create-skill` определяется по корню рабочей папки: есть `base/agents/`, `profiles/` и `scripts/build-plugins.py` — это кит, иначе проект. Интервью скилл ведёт в основном диалоге, агент только собирает файл, а записывает его скилл после твоего подтверждения. Локальные агенты и скиллы — часть проекта: закоммить их, и они будут у всей команды. Обновление кита их не трогает, пока имя не совпадёт с агентом или скиллом кита, поэтому билдер предлагает имя с префиксом проекта — см. [Известные ошибки](known-issues.md#свой-агент-или-скилл-с-именем-как-у-кита-перезаписывается).

## Работают сами

| Скилл | Что делает |
|---|---|
| `git-commit` | Сообщения коммитов по Conventional Commits, без `Co-Authored-By` и приписок «Generated with». Спрашивает сообщение или коммитит сразу — по настройке проекта |
| `git-branch` | Имена веток по Conventional Branch: `feat/…`, `fix/…`, `chore/…` |

Их не нужно вызывать: runtime применяет их каждый раз, когда создаёт коммит или ветку.

## Коммиты: с вопросом или без

Скилл `git-commit` всегда пишет сообщение по Conventional Commits и без соавторства. Спрашивать ли его перед коммитом, решает команда — поле `commit` в `.aikit/settings.json`:

| Значение | Что делает ассистент |
|---|---|
| `ask` (по умолчанию) | Предлагает 2–3 варианта сообщения и ждёт выбора |
| `auto` | Выбирает сообщение сам, коммитит и показывает хеш и сообщение |

`auto` снимает только вопрос о сообщении: ассистент коммитит, когда этого требует задача или ты просишь. Выбор делается при установке (`/aikit:setup`, `attach.sh --commit`, `install-adapter-package.py --commit`), меняется переключателем в AIKit Deck или правкой файла. Файл в git — настройка общая для команды.
