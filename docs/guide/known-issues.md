# Известные ошибки и ограничения

Что работает не так, как ожидается, и как это обойти. Список обновляется вместе с [roadmap](../roadmap.md): когда проблему чинят, запись отсюда убирают.

Чем отличаются Claude Code, Codex и OpenCode, описано на странице [Поддержка runtime](../runtime-support.md#3-известные-ограничения). Здесь — проблемы самого кита.


## Миграция исходников правил

Правила команды и профилей теперь находятся в `RULES.md`; инструкции runtime — в `adapters/<runtime>/rules.md`. Если у команды есть собственный профиль внутри исходников AIKit, перенеси его требования стека из `CLAUDE.md` в `RULES.md`. Автоматического fallback на инструкцию Claude у Codex нет: отсутствие нового источника считается ошибкой сборки.

Установленные проекты не требуют ручного удаления правил: повторный setup или обновление адаптера заменяет прежний блок AIKit, сохраняя текст команды вне блока. `attach.sh` и `update.sh` сохраняют свой прежний порядок обновления файла Claude.

## Установка

### Windows: нет команды python3

**Что происходит.** `attach.sh` предупреждает «python3 не найден» и продолжает. В результате нет `.aikit/profiles.json` и MCP-серверов, а `/implement-feature` потом пишет, что AIKit не установлен. На Windows Python часто доступен только как `python` или `py`.

**Как обойти.** Сделай `python3` доступным в Git Bash. Самый простой способ — копия интерпретатора под этим именем (так делает CI):

```bash
cp "$(command -v python)" "$(dirname "$(command -v python)")/python3.exe"
python3 --version
```

После этого запусти `attach.sh` ещё раз.

### Windows: python есть в PATH, но не запускается

**Что происходит.** В `PATH` первыми стоят `python.exe` и `python3.exe` из `WindowsApps` — заглушки Microsoft Store, а не Python: они открывают магазин или ничего не печатают. Лаунчер `py -3` тоже может быть сломан (например, `AssertionError: SRE module mismatch`, когда смешаны файлы разных версий). Скрипты кита и хуки тогда не запускаются, а хуки при этом не блокируют действия.

**Как обойти.** Проверь команду, которую вызывают хуки (`python3`, в Codex на Windows — `python`):

```bash
python3 -c "import sys; print(sys.executable, sys.version_info >= (3, 9))"
```

Должны напечататься путь не из `WindowsApps` и `True`. Если нет — поставь Python 3.9+ с python.org или через `winget` и выключи заглушки в «Параметры → Приложения → Псевдонимы выполнения приложений». `/aikit:setup` делает эту проверку сам, а запускались ли хуки на самом деле, узнаёт по отметкам (`aikit_hook.py --status`) и пишет результат в отчёт.

### Windows: ошибки кодировки в консоли

**Что происходит.** Скрипты кита печатают кириллицу и символы вроде `✓`. В консоли с кодировкой cp1251 Python может упасть с `UnicodeEncodeError`.

**Как обойти.** Перед запуском включи UTF-8 для Python:

```bash
export PYTHONIOENCODING=utf-8
```

Скрипты проверок кита (`scripts/ci/*.sh`) делают это сами.

В Windows PowerShell 5.1 `Get-Content` читает файлы без BOM в кодировке системы, и русский текст скиллов и правил приходит мусором вида `Р...`. Читай `Get-Content -Raw -Encoding UTF8 <файл>` — это правило есть в базовых правилах кита, но агент может о нём забыть.

### Смена профиля оставляет старых агентов

**Что происходит.** Если запустить `attach.sh` с другим профилем или пресетом, скиллы прошлой установки убираются, а агенты прежнего профиля остаются в `.claude/agents/`. В Codex и OpenCode такой проблемы нет: установщик адаптера убирает все файлы прошлой установки.

**Как обойти.** Удали агентов старого профиля вручную: их имена начинаются с префикса профиля (например, `vue-*`).

### update.sh перезаписывает CLAUDE.md целиком

**Что происходит.** У `CLAUDE.md` нет отдельного блока для правил проекта. Если ответить «да» на вопрос об обновлении, свои правки пропадут из файла. В режиме `--auto` вопроса нет совсем.

**Как обойти.** Перед обновлением сохраняется копия `CLAUDE.md.backup-<дата>` — перенеси из неё свои правила. Или отвечай «нет» и сравни вручную: `update.sh` покажет, где лежит новая версия. В Codex и OpenCode проблемы нет: AIKit пишет только свой блок в `AGENTS.md`.

### Свой агент или скилл с именем как у кита перезаписывается

**Что происходит.** Установщики кладут агентов и скиллы кита в те же папки, где лежат свои агенты и скиллы команды. Файлы с другими именами они не трогают. Если имя совпало с агентом кита, агент кита записывается поверх вашего файла (`.claude/agents/`, `.codex/agents/`, `.opencode/agents/`). Скилл с именем скилла кита в `.claude/skills/` `attach.sh` и `update.sh` не затирают: они пропускают его и пишут предупреждение, а скилл кита в этом случае не ставится. В `.agents/skills/` установщик Codex и OpenCode пересоздаёт папку скилла кита. Это касается и агентов и скиллов, которые появятся в ките позже.

**Как обойти.** Давай своим агентам и скиллам имена с префиксом проекта (`acme-l10n-checker`) — так их предлагают `/create-agent` и `/create-skill` в проекте. `.opencode/skills/` кит не трогает совсем.

### Codex не загружает свой агент в формате .md

**Что происходит.** Codex читает агентов только из `.codex/agents/*.toml`. Установщики кита и `/aikit:setup` свой `.md` в этой папке не трогают: не переводят в TOML и не удаляют, поэтому Codex такого агента не видит.

**Как обойти.** Пиши своих агентов Codex сразу в TOML (`name`, `description`, `developer_instructions`) — так делает `/create-agent`.

### Свой специалист в .aikit/profiles.json пропадает после обновления

**Что происходит.** Обновление кита сохраняет в `.aikit/profiles.json` только правки `commands`, `actions` и `root`, остальные поля переписывает из контрактов профилей. Свой агент, добавленный в `specialists`, после обновления исчезает, и `/implement-feature` перестаёт его звать.

**Как обойти.** После обновления верни запись в `specialists`. Чтобы специалист был постоянным, добавь его в контракт профиля в ките — PR в AIKit.

### Codex не видит агентов и MCP

**Что происходит.** Codex применяет `.codex/agents/` и `.codex/config.toml` только в доверенных проектах.

**Как обойти.** Отметь проект доверенным при первом запуске Codex. Подробнее — в `.codex/AIKIT.md` проекта после установки.

### Уведомление о новой версии AIKit

**Что происходит.** При установке плагинами хук старта сессии сравнивает версию установленного плагина с `VERSION` в `main` и один раз на версию пишет «AIKit: доступна версия X.Y.Z (у вас A.B.C)» с командами обновления. Для этого раз в сутки хук в фоне делает один сетевой запрос — забирает файл `VERSION` с `raw.githubusercontent.com` (таймаут 3 секунды) — и кладёт ответ в кэш `~/.cache/aikit/update-check.json` (на Windows — `%LOCALAPPDATA%\aikit\update-check.json`). Старт сессии сети не ждёт: хук читает только кэш, поэтому о новой версии ты узнаешь со следующей сессии после проверки. Без сети или за прокси уведомления просто нет. Работает только в проектах с `.aikit/` и только у плагинов — установка `attach.sh` и адаптерами обновляется через `update.sh` и `update-adapter-package.py`.

В Codex уведомление в начале сессии не проверено вживую: если Codex не покажет его сам, хук просит агента передать его в первом ответе. Хуки Codex работают после одобрения в `/hooks`, а на Windows — только с Python 3.9+ в PATH, см. [Codex на Windows](#codex-на-windows-хуки-могут-молча-не-работать).

**Как обойти.** Отключить проверку для себя — переменная окружения `AIKIT_NO_UPDATE_CHECK=1`, для всего проекта — `"update_check": false` в `.aikit/settings.json`. Показать уведомление снова — удали файл кэша.

### Плагин обновился, а версия осталась прежней

**Что происходит.** Плагин бывает установлен сразу в нескольких областях: для пользователя (`user`) и для проекта (`project`, `local`) — это видно в `installed_plugins.json` рядом с кэшем плагинов Claude Code (`~/.claude/plugins/`). `claude plugin update aikit@aikit` без `--scope` обновляет только одну запись, а сессия может грузить другую: команда пишет «обновлено», а после перезапуска шапка AIKit Deck и уведомление показывают старую версию.

**Как обойти.** Кнопки «Обновить кит» и «Обновить профиль» в [AIKit Deck](commands.md#панель-aikit-deck) обновляют все записи плагина для этого проекта сами. Вручную — по записи на область: `claude plugin update aikit@aikit --scope user`, затем `--scope project` (и `--scope local`, если есть) из папки проекта.

### AIKit Deck не открылась при старте сессии

**Что происходит.** Панель, которую мод открывает сам, Claude Code ставит только в широком окне терминала: от 144 колонок, а если ты её уже открывал — от 110. В более узком окне панель ждёт, пока ты не попросишь её сам. Кнопка «AIKit Deck» в строке режимов может появиться только после первого сообщения.

**Как обойти.** Нажми «Открыть» в строке «AIKit Deck» над полем ввода (она видна с начала сессии) или введи `/deck`. Ещё можно расширить окно терминала. Почему панель ждала, видно в debug-логе Claude Code (`claude --debug`): строка «AIKit Deck: панель ждёт размещения — …».

## Работа агентов

### Хуки Codex не работают до одобрения

**Что происходит.** Codex запускает хуки проекта только после того, как пользователь отметил их доверенными. Доверие привязано к содержимому, поэтому после обновления кита изменённые хуки снова выключены.

**Как обойти.** Открой `/hooks` в Codex и одобри хуки AIKit — после установки и после обновления, если Codex о них напоминает.

### Codex на Windows: хуки могут молча не работать

**Что происходит.** Повторная проверка (Codex CLI 0.163, октябрь 2026) показала: включённые и одобренные в `/hooks` хуки AIKit в живой сессии работают — загрузка памяти, защита `.env` через `apply_patch`, перенаправление и `Set-Content`, форматтер, ошибки линтера в контексте агента, блокировка `Stop` при падающих тестах. Но так только когда `python` в окружении хука — Python 3.9+. Если `python` — заглушка Microsoft Store, хук завершается с кодом 1, Codex не блокирует действие, и защита молча выключена. Одобрение хуков этого не меняет.

Три состояния не одно и то же: хуки *установлены* (плагин или `.codex/hooks.json`), *одобрены* (`/hooks`) и *выполняются* (Python запускается, скрипт отрабатывает). Первые два видно в Codex, третье — только по отметкам, которые хук оставляет при каждом запуске.

Ранее в ките были ошибки Windows-команд хуков Codex — исправлены. Codex запускает команду хука через `powershell -NoProfile -Command` или `cmd.exe`. Там не раскрывался `${PLUGIN_ROOT}`, относительный путь адаптера не находился из подпапки, Windows PowerShell 5.1 превращал код выхода 2 в 1, а Python 2 или старый Python 3 в PATH ронял лаунчер. Теперь команда — лаунчер `python -c`, без синтаксиса shell: он находит скрипт, передаёт событие Python 3.9+ (`py -3`, `python3`), если `python` старый, а блокирует хук ответом JSON `permissionDecision: deny`. Запись `.env` из подпапки блокируется и у адаптера, и у плагина; запись через PowerShell `Set-Content` тоже.

**Как проверить.** После подключения и перезапуска сессии запусти `/aikit:setup` ещё раз или выполни в проекте `python3 "<корень плагина>/base/hooks/aikit_hook.py" --status`. `state: ok` — хуки запускались; `no-mark` — ещё нет (в Codex проверь `/hooks`); `internal-error` — хук упал внутри, в `last_error` событие и текст ошибки; `launcher-error` — не нашёлся Python 3.9+. Отметки лежат во временной папке (`aikit-hooks`), содержимое файлов и события в них не пишется.

**Как обойти.** Сделай так, чтобы `python --version` показывал Python 3.9+ (см. «python есть в PATH, но не запускается»). Считай хуки страховкой: правила в `AGENTS.md` действуют и без них. После обновления кита одобри изменённые хуки в `/hooks` снова. Ограничения проверки: вложенная песочница Windows сама отклоняет часть записей — это не блокировка AIKit; полный цикл «тесты упали → блокировка → исправление → тесты прошли» в одной сессии вживую пока не подтверждён.

### Codex: субагенты не стартуют в codex exec --ephemeral

**Что происходит.** В Codex CLI 0.160.1 запуск субагента в сессии `codex exec --ephemeral` падает с `collab spawn failed: … no rollout found for thread id`. Агенты AIKit тут ни при чём: без `--ephemeral` те же агенты с теми же задачами отработали.

**Как обойти.** Сценарии с субагентами (`$implement-feature`, `$fix-bug`, `$security-check`, `$tech-debt` и другие) запускай в обычной, сохраняемой сессии — без `--ephemeral`.

### Хуки не видят обходные пути

**Что происходит.** Хук проверяет то, что агент пишет инструментами записи файлов и в командах `echo`, `printf`, `tee`, `>`, а в PowerShell — `Set-Content`, `Add-Content`, `Out-File`, `New-Item`, `Tee-Object` (и алиасы `sc`, `ac`) и `[IO.File]::WriteAllText` и похожие. Секрет, записанный другим способом (например, скриптом на Python, `Copy-Item` или переменной с именем файла), хук не увидит. Секреты он ищет по известным форматам ключей и токенов — пароль в открытом виде не распознает. Чтение `.env` запрещено только в Claude Code (`permissions` в `.claude/settings.json`): Codex и OpenCode задают запреты на чтение иначе.

**Как обойти.** Правила в `CLAUDE.md` и `AGENTS.md` остаются: хук — страховка, а не замена ревью.

### Хук тестов долгий на большом проекте

**Что происходит.** Когда агент закончил ответ и до этого правил код, хук запускает команду `test` профиля целиком. На проекте с долгими тестами ответ задерживается.

**Как обойти.** Поменяй `test` в `.aikit/profiles.json` на быструю команду (например, только unit-тесты) — хуки и `/implement-feature` возьмут её, обновление кита правку сохранит.

### Windows: хуки не запускают свои ./-скрипты

**Что происходит.** На Windows хуки запускают команды профиля через `cmd.exe`, а он не понимает путь вида `./script`. Обёртки Gradle и Maven хук запускает сам: `./gradlew` и `./mvnw` он заменяет на `.\gradlew` и `.\mvnw`, если рядом лежит `gradlew.bat` или `mvnw.cmd` (они есть в каждом wrapper). Свой скрипт без такой пары (`./scripts/test.sh`) хук не запустит и напишет «тесты не запустились — проверь вручную». Агенты и `/implement-feature` запускают команды через Bash, у них такие скрипты работают.

**Как обойти.** Положи рядом со скриптом `.cmd`-версию с тем же именем (`test.cmd` для `./test`) или запускай `test` профиля сам.

### Windows: npx и npm падают в PowerShell

**Что происходит.** Команды профиля вроде `npx vitest run` в PowerShell падают с «running scripts is disabled on this system»: PowerShell выбирает `npx.ps1`, а ExecutionPolicy запрещает скрипты. Так бывает у Codex, который запускает команды в PowerShell. Хуки кита команды профиля запускают через `cmd.exe`, их это не касается.

**Как обойти.** Базовые правила кита велят агенту вызвать `.cmd`-вариант той же команды (`npx.cmd vitest run`, `npm.cmd install`) или выполнить её в Git Bash. Политику системы менять не нужно. Если агент всё же спотыкается, можно поменять команды в `.aikit/profiles.json` на `.cmd`-варианты — обновление кита правку сохранит, но на macOS и Linux такие команды не работают.

### Forge 1.12.2: сборка падает не на JDK 8

**Что происходит.** Gradle 4.9 и ForgeGradle (3 в официальном MDK 14.23.5.2860, 2.3 в старых проектах) работают только на JDK 8. На JDK 11 и новее `./gradlew` падает до компиляции (`Unsupported class file major version`, `Could not determine java version`), и проверки профиля `forge-1-12-java` — `lint`, `test`, `build` — не проходят. Первая сборка скачивает и декомпилирует Minecraft — это несколько минут.

**Как обойти.** Укажи JDK 8 в `JAVA_HOME` (или `org.gradle.java.home` в `gradle.properties` на своей машине, не в git) и выполни команду `install` профиля — `./gradlew compileJava`. В ForgeGradle 2.3 исходники Minecraft для IDE даёт `./gradlew setupDecompWorkspace`; в ForgeGradle 3 такой задачи нет.

### Forge 1.12.2: «cannot find symbol setTranslationKey»

**Что происходит.** Имена методов Minecraft зависят от маппингов MCP в `build.gradle`. В официальном MDK (`snapshot_20171003-1.12`) метод называется `setUnlocalizedName`, в `stable_39` — `setTranslationKey`. Примеры из интернета и старые подсказки агента могут взять не тот вариант.

**Как обойти.** Агенты профиля берут имена из маппингов и кода проекта. Если сборка всё же упала с `cannot find symbol` — назови агенту маппинги из `build.gradle`; правило можно закрепить в `.aikit/memory/` через `/capture-memory`.

### Codex на Windows ищет python

**Что происходит.** На Windows Codex запускает хуки командой `python -c …` (`commandWindows`), а не `python3`. Лаунчер переживает Python 2 и старый Python 3 первым в PATH: он передаёт событие `py -3` или `python3` версии 3.9+. Если `python` — заглушка Microsoft Store, которая завершается с ошибкой, лаунчер не стартует вовсе: хуки не сработают, а действия не блокируются.

**Как обойти.** Сделай так, чтобы `python --version` показывал Python 3.9 или новее, или выключи заглушки `python.exe` и `python3.exe` в «Параметры → Приложения → Псевдонимы выполнения приложений».

### /implement-feature не проверен на живом проекте

**Что происходит.** CI проверяет установку: файлы на месте, контракты собраны, агенты и скиллы в правильном формате. Но полный прогон `/implement-feature` (с `--tdd` и `--worktree`), `/fix-bug`, `/check-feature` и пайплайна профиля в Claude Code и Codex на реальном проекте пока не делали. Шаги могут работать неидеально: например, агент неточно выберет профиль в монорепо.

**Как помочь.** Если цепочка повела себя странно, сохрани задачу и вывод и заведи issue. Такие прогоны — часть проверки этапов 3 и 5 roadmap.

### --worktree долго стартует и не видит .env

**Что происходит.** Worktree — чистая копия репозитория от последнего коммита. В ней нет `node_modules`, `.venv` и `.env`, а также твоих незакоммиченных правок. Зависимости ставятся командой `install` профиля при каждом запуске, а `.env` агент не копирует.

**Как обойти.** Для мелких задач запускай без `--worktree`. Если тестам или запуску нужны переменные окружения — положи `.env` в worktree сам, когда ассистент попросит. Нет `install` в `.aikit/profiles.json` — добавь (`npm ci`, `pnpm install`, `uv sync`).

### /check-feature без браузера проверяет только запросами

**Что происходит.** Для проверки UI нужен браузерный инструмент: Playwright MCP (его подключает профиль `vue-nuxt`) или встроенный браузер runtime. Без них `/check-feature` проверяет, что страница отдаётся и в ней есть нужный текст, а клики и формы оставляет тебе.

**Как обойти.** Подключи Playwright MCP или проверь UI вручную по сценарию, который покажет ассистент.

### OpenCode может сам запустить скиллы с побочными эффектами

**Что происходит.** В `SKILL.md` для OpenCode нет поля, которое запрещает автовызов. `/capture-memory`, `/optimize-memory` и `/set-model` могут сработать без явной просьбы.

**Как обойти.** Если такой скилл запустился без твоей просьбы, прерви его. Запрет можно задать через `permission` в `opencode.json`.
