# Установка и первая задача

Как подключить AIKit к проекту, что появится в репозитории и как запустить первую задачу. На всё уходит минут десять.

## Что нужно

| Что | Зачем | Примечание |
|---|---|---|
| Runtime | Claude Code, Codex или OpenCode | Подойдёт любой из трёх, можно несколько сразу |
| Python 3.11+ для Codex; 3.9+ для хуков | Codex читает нативные TOML через tomllib; хуки используют общий Python-обработчик | Команда `python3`; на Windows см. [Известные ошибки](known-issues.md#windows-нет-команды-python3) |
| Git | Маркетплейс плагинов — этот репозиторий на GitHub | Для установщика кит подключается как git submodule |
| Bash | Только для установщика `attach.sh` | На Windows — Git Bash (ставится вместе с Git for Windows) |
| `jq` | Склейка `settings.json` в `attach.sh` | Необязательно: без него сработает запасной путь на Python |

Кит ставится двумя способами:

- **плагинами** — Claude Code и Codex: агенты, скиллы, хуки и MCP приходят из маркетплейса и обновляются вместе с ним, в проект пишется только то, что принадлежит проекту;
- **установщиком** — OpenCode и запасной путь для Claude Code и Codex: кит подключается submodule'ом и копирует всё в проект.

Выбери один способ на проект: плагины и копии установщика вместе дублируют агентов и скиллы.

## Выбор набора

Проще всего взять пресет — готовую комбинацию профилей и паков:

| Пресет | Профили | Паки | Для кого |
|---|---|---|---|
| `frontend-team` | `vue-nuxt` | devops | Фронтенд на Vue/Nuxt |

Или собери набор сам — профили через `+`, паки отдельно. Анализ покрытия и техдолга (`/coverage-check`, `/tech-debt`) есть в ядре и работает через quality-специалиста каждого профиля — отдельный пак не нужен.

## Установка плагинами в Claude Code

Каждый профиль и пак — отдельный плагин маркетплейса `aikit`, ядро — плагин `aikit`.

<!-- steps -->
1. **Добавь маркетплейс и поставь плагины** — в Claude Code:

   ```text
   /plugin marketplace add undef1ned-dev/ai-kit
   /plugin install aikit@aikit
   /plugin install vue-nuxt@aikit
   /plugin install devops@aikit
   ```

   Ставь плагины профилей и паков своего набора.

2. **Подключи проект** — в корне проекта:

   ```text
   /aikit:setup frontend-team
   ```

   Аргумент — пресет или профили через `+`. Без аргумента скилл определит стек по проекту и предложит выбор. Ещё он спросит, как оформлять коммиты: предлагать 2–3 сообщения на выбор или коммитить сразу по тем же правилам ([подробнее](commands.md#коммиты-с-вопросом-или-без)).

3. **Заполни `PRODUCT.md`** в корне проекта: что за продукт, для кого, ключевые сущности. Агенты читают его перед решениями.

4. **Закоммить результат.** В `.claude/settings.json` записаны маркетплейс и включённые плагины: участник команды получит их, когда откроет проект и доверит папку.

Скиллы плагинов вызываются как `/name` или с именем плагина: `/aikit:implement-feature`, `/vue-nuxt:new-page`. Агенты плагинов называются с тем же префиксом: `aikit:memory-writer`, `vue-nuxt:vue-coder`.

В подключённом проекте сбоку открывается [панель AIKit Deck](commands.md#панель-aikit-deck): кнопки команд кита и профиля, справка и субагенты, которые сейчас работают. Закрыл — открой снова командой `/deck`.

## Установка плагинами в Codex

```bash
codex plugin marketplace add undef1ned-dev/ai-kit
codex plugin add aikit@aikit
codex plugin add vue-nuxt@aikit
```

Затем в корне проекта вызови скилл `$setup` с пресетом или профилями. Плагины Codex не умеют поставлять агентов, поэтому скилл записывает их в `.codex/agents/`. Правила проекта он кладёт блоком в `AGENTS.md`.

> [!IMPORTANT]
> Codex применяет агентов из `.codex/` только в **доверенном** проекте, а хуки запускает после одобрения в `/hooks`. Плагины Codex в AIKit проверены по формату, но ещё не прогонялись вживую — см. [Поддержка runtime](../runtime-support.md).

## Что появится в проекте при установке плагинами

| Файл или папка | Что это | В git |
|---|---|---|
| `CLAUDE.md` или `AGENTS.md` | Блок AIKit с [правилами проекта](glossary.md#правила-проекта): базовые плюс правила профилей. Текст вне блока не трогается | да |
| `.claude/settings.json` | Только Claude Code: разрешения на команды профиля, запрет чтения `.env`, без соавторства в коммитах, маркетплейс `aikit` и включённые плагины | да |
| `.codex/agents/` | Только Codex: агенты ядра, профилей и паков | да |
| `.aikit/profiles.json` | Контракты профилей: агенты по ролям, папка `root`, команды проверки | да |
| `.aikit/settings.json` | Настройки команды: `commit` — `ask` (варианты сообщения на выбор) или `auto` (коммит без вопроса); `update_check: false` — не сообщать о новой версии AIKit | да |
| `.aikit/profiles.kit-defaults.json` | Прежние значения кита — по ним повторный запуск сохраняет твои правки | да |
| `.aikit/plugin-init.json` | Выбранные профили и паки — для повторного запуска | да |
| `.aikit/memory/` | [Память проекта](glossary.md#память-проекта) | да |
| `PRODUCT.md` | Описание продукта — заполняет команда | да |

Хуки плагина работают только в проектах с папкой `.aikit/`: в других твоих проектах плагин ничего не проверяет.

У плагинов есть версия — та же, что в файле `VERSION` кита; она растёт автоматически после каждого слияния в `main`, которое меняет плагины. Когда в `main` выходит новая версия, при старте сессии AIKit один раз сообщает: «AIKit: доступна версия X.Y.Z (у вас A.B.C)» — подробнее в [Известных ошибках](known-issues.md#уведомление-о-новой-версии-aikit).

Обновление в Claude Code: `/plugin marketplace update aikit` обновляет каталог, затем `/plugin update aikit@aikit` (и так для каждого плагина профиля) обновляет сам плагин; изменения подхватываются после перезапуска сессии. В Codex — `codex plugin marketplace upgrade`; Codex сам обновляет плагины при смене версии в маркетплейсе, но агентов в `.codex/agents/` плагин не обновляет — после обновления запусти в проекте `$aikit:update-agents`: он пересоберёт только агентов, не трогая правила и настройки. Чтобы сменить набор профилей, запусти `/aikit:setup` заново — лишние агенты Codex уберутся, правки команды в `.aikit/profiles.json` сохранятся.

## Установка установщиком в Claude Code

<!-- steps -->
1. **Подключи кит к репозиторию проекта.** Из корня проекта:

   ```bash
   git submodule add git@github.com:undef1ned-dev/ai-kit.git .aikit-config
   git submodule update --init
   ```

2. **Запусти установщик** с пресетом или своим набором:

   ```bash
   bash .aikit-config/scripts/attach.sh --preset frontend-team
   bash .aikit-config/scripts/attach.sh vue-nuxt --pack devops
   ```

   В терминале установщик спросит, как оформлять коммиты; без вопроса — флаг `--commit ask` или `--commit auto`.

3. **Заполни `PRODUCT.md`** и **закоммить результат** — установка состоит из обычных файлов в репозитории.

## Что появится в проекте при установке установщиком

| Файл или папка | Что это | В git |
|---|---|---|
| `CLAUDE.md` | [Правила проекта](glossary.md#правила-проекта): базовые плюс правила профилей | да |
| `.claude/agents/` | Агенты ядра, профилей и паков | да |
| `.claude/skills/` | Скиллы: `/name` или автовызов по описанию | да |
| `.claude/settings.json` | Разрешения на команды профиля, запрет чтения `.env`, без соавторства в коммитах, подключение хуков | да |
| `.aikit/hooks/aikit_hook.py` | [Хуки](how-it-works.md#хуки-правила-которые-соблюдаются-всегда): правила коммитов, веток и секретов, линтер после правки, тесты в конце ответа | да |
| `.mcp.json` | MCP-серверы | да |
| `.aikit/profiles.json` | Контракты профилей: агенты по ролям, папка `root`, команды проверки | да |
| `.aikit/settings.json` | Настройки команды: `commit` — `ask` (варианты сообщения на выбор) или `auto` (коммит без вопроса) | да |
| `.aikit/profiles.kit-defaults.json` | Прежние значения кита — по ним обновление сохраняет твои правки | да |
| `.aikit/memory/` | [Память проекта](glossary.md#память-проекта) | да |
| `PRODUCT.md` | Описание продукта — заполняет команда | да |
| `.claude/.config-version` | Что и какой версии установлено — для `update.sh` | да |

> [!NOTE]
> В монорепо установщик сам найдёт папку каждого профиля по маркерам: `web/nuxt.config.ts` → профиль `vue-nuxt` живёт в `web/`. Найденная папка записывается в `root` в `.aikit/profiles.json`. Если угадал неверно — поправь `root` вручную, обновление правку сохранит.

## Первая задача

Открой runtime в корне проекта (`claude` в терминале или проект в приложении) и дай задачу:

```text
/implement-feature страница профиля пользователя: аватар, имя, email, кнопка «Выйти»
```

Ассистент выберет профиль, проведёт задачу через архитектора, кодера, тестировщика и ревьюера, запустит линтер и тесты и покажет итог. Если агенту что-то неясно, он остановится и спросит — отвечай на вопросы, это нормально.

Как формулировать задачи, чтобы результат был лучше, — на странице [Работа с агентами](daily-work.md).

## Установка установщиком в Codex и OpenCode

Кит подключается так же, submodule в `.aikit-config`, а ставит его установщик адаптера:

```bash
python3 .aikit-config/scripts/install-adapter-package.py codex --preset frontend-team --workspace .
```

Вместо `codex` — `opencode`. Вместо `--preset` можно указать `--profile vue-nuxt` и `--pack devops`. `--commit auto` — коммитить без вопроса о сообщении (по умолчанию `ask`).

Что появится: блок AIKit в `AGENTS.md` (твой текст вне блока сохраняется), скиллы в `.agents/skills/`, агенты в `.codex/agents/` или `.opencode/agents/`, MCP-серверы в `.codex/config.toml` или `opencode.json`, хуки в `.codex/hooks.json` или плагином `.opencode/plugins/aikit-hooks.js`, те же `.aikit/profiles.json`, `.aikit/settings.json`, `.aikit/hooks/` и `.aikit/memory/`.

> [!IMPORTANT]
> Codex применяет агентов, MCP и хуки из `.codex/` только в **доверенном** проекте. Отметь проект доверенным при первом запуске Codex — иначе агенты AIKit не загрузятся. Хуки Codex запускает только после одобрения: открой `/hooks` и отметь хуки AIKit доверенными; после обновления кита, если хуки изменились, — ещё раз. Figma и Sentry в Codex авторизуются командой `codex mcp login <name>`.

Скиллы в Codex вызываются через `$name` (например, `$implement-feature`), список — `/skills`. Остальные отличия runtime собраны на странице [Поддержка runtime](../runtime-support.md).

## Проверка готовности Codex

При установке плагинами вызови `$aikit:setup --check`. Режим не запускает подключение заново, не меняет профили и настройки и не спрашивает режим коммитов. После обычного setup скилл также использует этот отчёт для Codex.

При установке адаптером:

```bash
python3 .aikit/scripts/codex-doctor.py --workspace .
```

Нужен Python 3.11+. Для машинного отчёта добавь `--json`. Скрипт не запускает модель, команды профиля или серверы MCP; запросы `plugin list` и `mcp list` читают эффективную конфигурацию CLI. Значения секретов и содержимое ошибок хуков не выводятся.

Статусы: `ok` — проверена конфигурация или найдена недавняя отметка; `warning` — требуется внимание; `error` — найдена ошибка; `unknown` — данных недостаточно. Код выхода 1 означает наличие `error`, код 0 не означает полной готовности активной сессии. Доверие из пользовательского файла не доказывает отсутствие управляемых ограничений. Одобрение текущих хуков проверь в `/hooks`, загрузку новых агентов — в новой сессии. Наличие MCP и OAuth-учётных данных не подтверждает рабочее соединение.

История хуков учитывается отдельно для Codex: отметки старше суток, чужого runtime или старого общего формата не считаются подтверждением текущей работы. Обнови хуки и повтори проверку после новой сессии. Общая ошибка лаунчера без отметки проекта — подсказка, а не доказательство сбоя именно этого проекта.

## Обновление установки

### Плагины Codex

В подключённом проекте вызови:

```text
$aikit:update-agents --with-plugins
```

Нужен Python 3.11+. Единый режим обновляет только маркетплейс `aikit` (все установленные из него плагины), проверяет версии ядра и выбранных профилей и паков и пересобирает агентов из свежего источника. Другие маркетплейсы не затрагиваются. Итог показывает версии до и после; открой новую сессию Codex, при изменении хуков одобри их повторно в `/hooks`.

Правила, контракты, память и настройки команды этот режим не меняет; для обновления правил или смены профилей используй `setup`. Свои агенты сохраняются. Сбой обновления или пересборки оставляет прежних агентов; сбой записи откатывает файлы проекта. Сам обновлённый маркетплейс назад не откатывается. Если ядро и плагины разошлись по версиям, скрипт остановится с ошибкой.

Без флага `$aikit:update-agents` сохраняет прежний режим: только пересборка агентов после ручного обновления плагинов и новой сессии.

### Установка адаптером

Claude Code:

```bash
bash .aikit-config/scripts/update.sh          # с вопросами
bash .aikit-config/scripts/update.sh --auto   # без вопросов
```

Codex и OpenCode:

```bash
python3 .aikit-config/scripts/update-adapter-package.py codex --preset frontend-team --workspace .
```

Что происходит при обновлении:

- кит подтягивает свежую версию — только если подключён как submodule и в нём нет локальных правок;
- агенты и скиллы кита перезаписываются — свои правки в них не делай, они потеряются;
- **`CLAUDE.md`** — `update.sh` покажет разницу и спросит, обновлять ли. При согласии старый файл сохранится в `CLAUDE.md.backup-<дата>`. В `--auto` файл обновляется без вопроса;
- **`.aikit/profiles.json`** — команды и `root`, которые поменяла команда, сохраняются; не тронутые — обновляются до новых значений кита;
- MCP-серверы и хуки, которые ты добавил сам, сохраняются; хуки AIKit обновляются.

Чтобы сменить пресет или набор профилей, запусти установщик заново с новым набором. В Codex и OpenCode файлы прошлой установки убираются. `attach.sh` убирает только скиллы, а агенты прежнего профиля остаются в `.claude/agents/` — удали их вручную (см. [Известные ошибки](known-issues.md#смена-профиля-оставляет-старых-агентов)).

## Проект, где кит уже подключён

Если кит стоит плагинами, открой проект в Claude Code и доверь папку — маркетплейс и плагины подтянутся из `.claude/settings.json`. В Codex добавь маркетплейс и плагины командами выше.

Если кит стоит установщиком, подтяни submodule — остальное уже в git:

```bash
git clone <url-проекта>
cd <проект>
git submodule update --init
```
