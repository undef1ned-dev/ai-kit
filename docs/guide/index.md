# Что такое AIKit

AIKit — набор готовых правил, агентов и команд для AI-ассистентов, которые пишут код: Claude Code, Codex и OpenCode. Одна команда подключает его к проекту. После этого ассистент знает стек проекта и правила команды и ведёт фичу по одной цепочке: план → код → тесты → ревью.

## Зачем это нужно

AI-ассистент из коробки — сильный разработчик, который впервые видит ваш проект. Он не знает:

- какой у вас стек и как устроены папки;
- как в команде принято называть файлы, писать тесты и коммиты;
- что нельзя трогать (секреты, `.env`) и чем проверять код.

Без подготовки каждый разработчик объясняет это ассистенту заново, своими словами, и результат каждый раз разный. AIKit решает это один раз для всей команды: правила, роли и сценарии лежат в одном репозитории и ставятся в любой проект одинаково.

> [!TIP]
> Удобная аналогия: AI-ассистент — новый сотрудник, AIKit — его онбординг-пакет. В нём регламент команды (правила проекта), должностные инструкции (агенты), чек-листы типовых процессов (скиллы) и доступы к инструментам (MCP-серверы).

## Как выглядит работа

Ты пишешь ассистенту одну команду:

```text
/implement-feature страница уведомлений с фильтром «непрочитанные» и кнопкой «прочитать все»
```

Дальше AIKit ведёт задачу по цепочке агентов профиля. Каждый агент — отдельная роль со своей инструкцией:

<!-- chain -->
- **architect** — читает проект и пишет план: какие файлы создать и изменить
- **coder** — реализует план
- **tester** — пишет тесты на сделанное
- **reviewer** — проверяет код по правилам стека

В конце ассистент запускает линтер и тесты проекта и показывает итог: какие файлы созданы, прошли ли тесты, что заметил ревьюер. Подробно шаги разобраны в разделе [Как это работает](how-it-works.md).

## Из чего состоит кит

<!-- cards -->
- [Правила проекта](glossary.md#правила-проекта) — `CLAUDE.md` / `AGENTS.md`: стек, архитектура, запреты; ассистент читает их в начале каждой сессии
- [Агенты](glossary.md#агент) — роли с инструкциями: архитектор, кодер, тестировщик, ревьюер, аналитик, аудитор безопасности
- [Скиллы](glossary.md#скилл) — готовые сценарии, которые вызываются командой: `/implement-feature`, `/security-check`, `/new-page`
- [Профили](glossary.md#профиль) — всё под один стек: сейчас Vue/Nuxt; новый стек добавляется по шаблону
- [Паки](glossary.md#пак) — дополнения под задачу, а не стек: качество кода, DevOps, AI-интеграции
- [MCP-серверы](glossary.md#mcp-сервер) — инструменты для ассистента: браузер Playwright, документация библиотек, Figma

## Какие AI-ассистенты поддерживаются

| Runtime | Статус | Как ставится |
|---|---|---|
| **Claude Code** | основной | плагины маркетплейса `aikit` или `attach.sh` |
| **Codex** (CLI, Desktop, IDE) | основной, наравне с Claude Code | плагины маркетплейса `aikit` или `install-adapter-package.py codex` |
| **Antigravity** (Antigravity 2.0, IDE, CLI) | поддерживаемый | плагины (`install-antigravity-plugins.py` + `plugin-init.py --runtime antigravity`) или `install-adapter-package.py antigravity` |
| **OpenCode** | поддерживается всё, что позволяет runtime | `install-adapter-package.py opencode` |

Агенты, скиллы и правила описаны один раз, а установщик раскладывает их в родной формат каждого runtime. Что где работает и чем отличается — на странице [Поддержка runtime](../runtime-support.md).
