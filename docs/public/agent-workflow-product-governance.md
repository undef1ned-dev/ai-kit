# Agent Workflow Product Governance

This document closes the product-layer governance portion of Phase 15 before the final roadmap analysis.

| Surface | Status | Contract |

## Governance Rules

- Keep all product surfaces local and private-repository compatible.
- Do not introduce GitHub Pages or public hosting as a requirement.
- Keep generated HTML tied to source files through generators and validators.
- Route user-facing workflow starts through profile, runtime, skill, context and validation decisions.
- Treat static docs and fixtures as source-backed guidance, not live runtime verification.

## Adoption Path

1. Start with [docs/local-docs-portal.md](./local-docs-portal.md).
2. Pick a product path in [docs/product-story.md](./product-story.md).
3. Inspect [docs/catalog.html](../catalog.html) and [docs/catalog-ux-v2.md](./catalog-ux-v2.md).
4. Choose a template in [docs/workflow-presets-task-templates.md](../internal/workflow-presets-task-templates.md).
5. Use [docs/choose-best-agent-flow.md](../internal/choose-best-agent-flow.md) to explain profile, runtime and skill selection.
6. Validate the selected path before implementation is considered done.
